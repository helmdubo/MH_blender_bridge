## Контекст проекта, зафиксированный owner

Эти решения закрывают целые направления. Не переоткрывать.

1. **UE5 — сцена для рендера портфолио.** Игровых объектов, Blueprint-акторов
   и геймплейной логики нет и не планируется.
2. **Обратной записи в Dagor не будет никогда.** Dagor — донор данных для
   Blender и UE5, односторонне.
3. **Функции прижатия объектов в UE5 не будет.**
4. **Рабочий маршрут owner — на 100%** Dagor CDK → dag4blend → сцена Blender →
   mh4blend → `.composite` + `.mesh.fbx` + `.material` → UE5.

## 0. Смена курса относительно редакции 1

Редакция 1 описывала мост с материализацией: конвертер строил MH-DTO, затем
**создавал новые MH-коллекции рядом** с даговскими, экспортёр обходил их, а
внешние placement'ы приходилось перепривязывать со старых коллекций на новые.

Этот двойник и был источником блокера. Старые Empty продолжали инстансировать
оригинал, строгий экспортёр видел неусыновлённую зависимость и справедливо
отказывал.

Редакция 2 убирает двойника из обязательного маршрута. Даговская сцена
остаётся authoring-представлением и читается адаптером напрямую. Перепривязывать
становится нечего — проблема исчезает, а не решается.

## 1. Целевой маршрут

```text
                    ВЫБРАННАЯ КОРНЕВАЯ КОЛЛЕКЦИЯ
                              │
                    определение формы сцены (read-only)
                              │
            ┌─────────────────┴─────────────────┐
            │                                   │
       MH Scene Adapter                 dag4blend Scene Adapter
       (существующий reader)            (import_dagor_composite)
            │                                   │
            └─────────────────┬─────────────────┘
                              ▼
                    ОДИН MH Composite DTO Bundle
              documents / mesh inputs / provenance
                              │
                              ▼
                 ОДИН Source Closure Builder
                              │
              ┌───────────────┼────────────────┐
              ▼               ▼                ▼
      composite_json_bytes  prepare_fbx    material writer
              │            _collection          │
              └───────────────┼────────────────┘
                              ▼
                 ОДИН упорядоченный публикатор (S4)
                              │
                              ▼
     materials → meshes → nested composites → root composite
```

**Обязательный инвариант среза:**

```text
две формы сцены Blender → один тип DTO → один канонический писатель
```

Адаптер даговской сцены **только читает другое представление**. Он не
создаёт и не изменяет ни одного Blender-датаблока.

## 3. Границы маршрута — что теряется до MH

dag4blend разбирает `.composit.blk` своим списком `separate_by`
(`prog/tools/dag4blend/cmp/cmp_import.py`) и кладёт распознанное в `dagorprops`
на Empty.

**Доезжает до Blender:**

```text
place_type:i, placeOnCollision:b, ignoreParentInstSeed:b,
rot_*/offset_*/scale/yScale:p2, include, weight:r, type:t, name:t
```

**Теряется самим dag4blend, до MH:**

```text
aboveHt:r, useCollisionNormal:b, quantizeTm:b, label:t, colors, require,
xScale, snake_case-алиасы (place_on_collision, use_collision_norm),
свойства корневого блока композита
```

Для потерянного MH делать нечего. По корпусу (26 089 файлов, отчёт
`reference_notes/dagor_corpus_inventory_20260828.md`): `aboveHt` 14 файлов,
`useCollisionNormal` 8, `quantizeTm` 3; `label`, `colors`, `require` — ноль.

**Эпистемическая граница, которую нельзя нарушать.** Отсутствие свойства в
сцене **не доказывает**, что в исходном BLK стоял ноль или что его там не было.
Адаптер сохраняет то, что физически лежит в custom properties, и в отчёте
называет то, чего знать не может. Он не выводит и не восстанавливает
наследование от корневого блока.

## 4. Диспетчер формы сцены

Автовыбор адаптера безопасен, потому что он **read-only**. Это не то же самое,
что молча конвертировать сцену: выбор читателя — чтение, конвертация —
создание и изменение датаблоков. Первое допустимо при обычном Export, второе
остаётся отдельной необязательной командой.

Диспетчер строгий:

```text
has_mh    = "mh_resource_kind" in collection, "mh_resource_name" in collection
has_dagor = "type" in collection, "name" in collection

частичная MH-идентичность (одно из двух)      → отказ
MH-идентичность вместе с даговской            → отказ, смешанный authority
даговская идентичность                        → require type == "composit"
                                                 require каноническое имя
                                                 → DAG4BLEND adapter
иначе                                          → MH adapter
```

Отказы идут существующим `MH_E_INVALID_RESOURCE_SOURCE` с именем коллекции и
перечислением найденных маркеров. Нового семейства кодов не вводится.

## 5. Что удалить из обязательного маршрута

1. **Материализация после публикации.** Из публикующей функции убрать вызов
   `materialize_composite_documents(...)`. После
   `publish_composite_closure_export(...)` операция завершается отчётом.
2. **Перепривязка.** `_dag4blend_external_relinks`,
   `_schedule_dag4blend_relinks`, карта «старая коллекция → новая managed».
   Могут остаться только внутри необязательной команды §11, и там — за
   отдельной явной галочкой.
3. **Создание MH composite-коллекций в Blender.** Прямой экспорт создаёт
   только файлы в Source Root.
4. **MH-метки на исходных даговских коллекциях.** `mh_resource_kind` и
   `mh_resource_name` **не ставятся**. Коллекция не стала MH-определением: её
   прочитал специальный адаптер, она остаётся dag4blend-form authoring input.
   Метки создали бы смешанную форму и снова размыли границу из §4.
   Следствие: общий `_finalize_published_blender_state(...)` для этого
   маршрута **не вызывается**; нужен собственный финализатор без мутаций —
   receipt файловой публикации, лог, обновление UI, ноль изменений датаблоков.
5. **Blender ID preflight для будущей материализации.** Проверки, резервирующие
   имена создаваемых коллекций и объектов, убрать. `_validate_document_mapping`
   оставить как DTO-валидацию. `definition_policy` REUSE/REFRESH прямому
   экспорту не нужен.

**Следствие пункта 4, которое обязано быть реализовано явно.** Раз меток нет,
Blender-сцена не может служить признаком «это уже опубликовано».
Переиспользование существующих payload'ов проверяется **против Source Root**
(инвентаризация источника + сравнение содержимого), а не против меток в сцене.
Без этого повторный экспорт будет переписывать все FBX и материалы каждый раз.

## 6. Блокеры — снять

Каждый начинается с failing-теста на текущем `origin/main`, вывод которого
попадает в квитанцию.

### 6.1 Пустой random-вариант

`ent{name:t=""; weight:r=2}` — легальная конструкция Dagor: в `loadAddEnt`
пустой вариант кладётся как `Obj` с `ent == nullptr` и участвует в рулетке
наравне с остальными. Идиома «здесь с некоторой вероятностью не будет ничего».

Сейчас читатель падает:

```python
option_collection = option_obj.instance_collection
if option_collection is None:
    _raise("MH_E_COMPOSITE_GRAMMAR", ...,
           "dag4blend random option requires explicit resource collection")
```

Должен давать `RandomOption(kind="empty", weight=N, resource=None)`.

Семантика Dagor, воспроизвести точно:

- пустой вариант сохраняется, **только если у того же узла есть хотя бы один
  непустой вариант**; узел, все варианты которого пустые, не порождает ничего;
- вес пустого варианта участвует в нормализации наравне с остальными.

**Грамматика не меняется** — `kind: "empty"` уже есть. Это дефект читателя.

Дополнительно: посчитать по корпусу число файлов с пустым `ent` и записать в
квитанцию — в инвентаризации такой строки нет.

### 6.2 Три режима экспорта вместо жёстко зашитого include-all

WIP-планировщик строит `CLOSURE_MODE_INCLUDE_ALL` безусловно. Параметризовать
теми же тремя режимами, что уже есть у обычного closure exporter, и научить
все три существующие команды принимать обе формы сцены:

| Команда | Поведение на даговском корне |
| --- | --- |
| `Export Composite` | публикует только root `.composite`; все исключённые зависимости обязаны существовать в Source Root |
| `Export Composite + Composite Closure` | публикует root и все вложенные `.composite`; mesh/material только валидируются и переиспользуются из Source Root |
| `Export Composite Include All Stuff` | публикует placement profiles, материалы, меши, вложенные композиты, root; текстуры — только валидация, как сейчас |

**Записать в документации команды:** на свежеимпортированной из CDK сцене
режим root-only будет отказывать почти всегда, потому что ни один меш и
материал ещё не лежат в Source Root. Это корректное поведение, а не регрессия;
рабочий режим для CDK — include-all.

### 6.3 «Вся сцена» = достижимое замыкание корня

Под «выгрузить всю `.blend` сцену» понимается **полное достижимое замыкание
выбранного корневого композита**, а не все датаблоки файла:

```text
входит:  все дочерние узлы
         все ссылки на вложенные композиты
         ВСЕ варианты всех random-узлов, включая невыбранный и zero-weight
         все используемые rendinst/prefab-определения и их LOD
         все используемые материалы
         все текстурные зависимости (для валидации)

не входит: посторонние коллекции, другие открытые композиты,
           недостижимое от корня, чужие материалы,
           TECH_STUFF/TECH хелперы как самостоятельные ресурсы,
           preview-only объекты
```

Обход random идёт **по всем вариантам**, а не по видимому в Blender.

### 6.4 `gameObj` → `marker`

**Owner-решение.** В UE5 нет и не будет игровых объектов и Blueprint-акторов;
UE5 — сцена для рендера портфолио. Даговский `gameObj` должен сохранять имя и
трансформ, участвовать в иерархии и **не порождать в UE ни актора, ни кода**.

Сейчас `gameObj` мапится в `actor`. `actor` в MH имеет исполняемую семантику
через ActorClassRegistry, то есть означает «заспавнить класс». Кодировать
маркер через `actor` можно только скрытым флагом внутри него, а это хуже
отдельного вида.

`group` не подходит: он отсутствует в `_OPTION_KINDS`, а даговский лут обычно
лежит **внутри** random-узла. Кодировать варианты как `empty` — значит склеить
разные именованные маркеры в неразличимые пустоты и потерять, какой выпал.

**Поправка к протоколу: новый kind `marker`.**

```json
{ "kind": "marker", "resource": "dummy_pivot", "transform": { } }
{ "kind": "marker", "resource": "loot_spawn_a", "weight": 1 }
```

- добавляется в `_KINDS`, `_RESOURCE_KINDS` и `_OPTION_KINDS` на стороне
  Blender и в зеркальный `EMHRandomSemanticKind` на стороне UE;
- участвует в иерархии, сохраняет имя ресурса и трансформ;
- **не порождает лист**: в плане присутствует узел, в `Leaves` — ничего.
  Образец реализации на стороне UE — существующая обработка `group`;
- как вариант random участвует в розыгрыше и записывается в `Decisions`,
  материализуя ничего;
- реестр ролей `gameObj` **не нужен**: правило одно для всех 386 имён корпуса.

**Почему поправка внутри среза, а не отдельно.** Она заявлена открыто,
ратифицирована owner и необходима для собственной цели среза — `gameObj`
является одним из четырёх блокеров. Ни один существующий `.composite` вида
`marker` не содержит, поэтому golden-векторы не перегенерируются. Это не
случай `21624a7`: там объём был нераскрытым.

Записать в `docs/10_source_protocol_v5_plan.md` как поправку к §6.1 в том же
PR. `OPEN-V5-19` (блокировка actor-содержащих замыканий) закрывается этим
решением.

## 7. Носители — сохранять, не исполнять

Оба поля опциональны и опускаются при дефолте, поэтому существующие
`.composite` остаются байт-идентичными. Резолвер, layout-подпись и
golden-векторы не затрагиваются: это метаданные источника, входящие только в
source/closure hash.

### 7.1 `placement` — носитель узлового `place_type`

**Честное обоснование, изменившееся после owner-решений.** Обратной записи в
Dagor не будет, прижатия в UE5 не будет. Значит это поле **не функциональное,
а провенансное**: оно фиксирует исходное намерение и предотвращает тихую
потерю данных, но потребителя у него нет и не появится.

Owner подтвердил, что информацию нужно оставлять в ассете. Стоимость поля
близка к нулю, повторное получение потребовало бы заново прогонять импорт из
CDK. Поэтому носитель вводится — но в документе и в коде он помечен как
провенанс, чтобы никто позже не начал строить на нём логику.

Формат — как в документе 12: опциональный объект узла с обязательным `mode` из
закрытого множества
`pivot | pivot_normal | three_point | foundation | water | pivot_collision`.
Отсутствие блока = «не прижимать» = `place_type:i=0`. Значение вне `0…6`
блокирует `MH_E_COMPOSITE_GRAMMAR`. `placeOnCollision:b=yes` без явного
`place_type` → `mode: pivot`; явный `place_type` перебивает флаг.

`trace_start_above_cm` **не вводится**: `aboveHt` теряется dag4blend'ом.
Наследование от корневого блока **не восстанавливается** (§3).

### 7.2 `appearance_seed_boundary` — носитель `ignoreParentInstSeed`

Сейчас теряется молча. По корпусу 190 файлов, 660 вхождений, через dag4blend
доезжает целым. В отличие от 7.1 это поле **функциональное**: в V5-S6.3 оно
станет границей сида покраски и будет реально работать. Для сцены-портфолио
вариативность цвета и износа — прямо видимый результат.

В этом срезе — только носитель: опциональный bool узла, дефолт `false`,
опускается когда `false`, потребителя пока нет. `useParentInstSeed` по корпусу
ноль вхождений; принимается как явный `false`.

## 8. Контракт частичной совместимости

Адаптер даговской сцены **не является lossless-конвертером исходного BLK** и не
должен так называться. Часть данных dag4blend теряет до запуска MH (§3).

```text
Читатель Dagor BLK напрямую (core/dagor_composites.py, путь (a)):
    lossless / fail-closed по поддерживаемой грамматике

Адаптер даговской сцены Blender (этот срез, путь (b)):
    частичная совместимость по форме сцены
```

Операция выводит отчёт о совместимости, например:

```text
Экспорт даговской сцены: совместимость

Сохранено:
    иерархия, parent-local трансформы, random-варианты и веса,
    вложенные композиты, ссылки на rendinst, LOD мешей, материалы,
    узловой place_type, ignoreParentInstSeed, маркеры gameObj

Невосстановимо из этой формы сцены:
    свойства корневого блока композита, aboveHt, useCollisionNormal,
    quantizeTm, label, require, colors

Заблокировано:
    prefab без явной политики
    inline p2 без типизированного профиля
```

Отчёт **не блокирует** базовый экспорт: owner сознательно выбрал маршрут
частичной совместимости.

### Что остаётся заблокированным

**Inline p2 без типизированного профиля.** Решение по `OPEN-V5-15` не принято,
временное правило — блокировка. Диагностика обязана называть NodePath **и
перечислять конкретные параметры**, вызвавшие отказ. По корпусу 453 файла,
в mall 6; доминирует одиночный `rot_y` (365 файлов).

**Dagor `prefab`.** Fail-closed по умолчанию с явным opt-in
`Allow Prefab as Mesh (Lossy)`; при включении — warning о том, что
collision/gameplay-семантика не сохраняется. По корпусу 807 файлов, в mall ноль.

**`label`, `require`, `colors`.** Ноль вхождений в корпусе и теряются самим
dag4blend. Останавливать импорт на них **не нужно**. Если конструкция всё же
дойдёт — drop с `MH_W_DAGOR_CONSTRUCT_DROPPED`, называющим NodePath.
`require` остаётся никогда не исполняемым: это topology semantics, исполнение
потребовало бы входа в резолвер и в подпись.

## 9. Acceptance

1. **Красные прогоны до изменений** для каждого блокера §6, вывод в квитанции.
2. **Нулевая мутация сцены.** До и после любого прямого экспорта совпадают:
   число Scenes / Collections / Objects, все указатели `instance_collection`,
   все `parent`, все custom properties коллекций и объектов, все имена,
   активная сцена, выделение. Разрешены только лог, файлы и отчёт.
3. **Две формы — байт-идентичный JSON.** Одна логическая структура, собранная
   в native MH-форме и в dag4blend-форме, даёт `DTO_A == DTO_B` и
   `composite_json_bytes(A) == composite_json_bytes(B)` байт в байт.
4. **Пустой вариант.** Композит с `ent{name:t=""; weight:r=2}` рядом с
   реальным вариантом импортируется; вес участвует в нормализации; узел, все
   варианты которого пустые, не порождает ничего.
5. **Полное замыкание.** Root, вложенные композиты, все варианты random,
   пустой вариант, zero-weight вариант, mesh- и material-зависимости.
   Невыбранная ветка обязана попадать в замыкание.
6. **Три режима.** Отдельные тесты на `root_only`, `composite_closure`,
   `include_all`.
7. **GAZ-53 end-to-end.** Импортированная dag4blend сцена → прямой экспорт →
   три `.composite`, композиты вариантов, все загруженные mesh FBX, все
   представимые материалы. **Без появления в Blender ни одной новой MH-коллекции.**
   Фикстура из `fixture_sources/`, не синтетическая.
8. **Повторный экспорт.** Второй прогон на неизменённой сцене: те же
   канонические байты, те же идентичности ресурсов, ни одного нового
   датаблока, существующие payload'ы **переиспользованы из Source Root**, а не
   переписаны.
9. **Частичная публикация.** Инъекция сбоя на каждой границе замены:
   замкнутый префикс, root никогда не опубликован раньше зависимостей,
   повторный запуск завершает батч, сцена не изменена.
10. **`marker`.** Композит с `dummy_pivot` и с `loot_*` внутри random-узла
    импортируется; в UE не создаётся ни одного актора; имя и трансформ
    присутствуют в плане; выбранный вариант записан в `Decisions`; в `Leaves`
    маркеров нет. Обе стороны знают новый kind, кодек симметричен.
11. **Носители.** Композит с `place_type:i=3` и `ignoreParentInstSeed:b=yes`
    даёт оба значения в канонических байтах; мировые матрицы и поведение UE
    байт-идентичны случаю без них.
12. **Отчёт о совместимости** формируется и называет сохранённое,
    невосстановимое и заблокированное.
13. **Регрессия.** Существующие golden-векторы, `ResolvedSignature`, choices,
    samples и world transforms байт-идентичны состоянию до среза. Обычные
    команды на MH-форме сцены ведут себя ровно как раньше.
14. Python + Blender suite, оба unity-гейта, packaged smoke.
