## 0. Что уже есть в репозитории — не переписывать

Проверено по коду. Исполнитель обязан сначала **установить фактическое
поведение failing-тестом**, а не переделывать работающее.

| Механизм | Где | Состояние |
| --- | --- | --- |
| Пустой вариант в грамматике | `core/composites.py::_OPTION_KINDS` | `"empty"` **уже есть**, `resource` для него запрещён. Грамматику менять не нужно |
| Конвертер сцены | `scene/import_dagor_composite.py` | Работает: рекурсия, parent-local, random-хелперы, `weight:r` |
| Оператор конвертации | `ui/ops.py::MH_OT_convert_dag4blend_composite` | Существует |
| Actor как транспортный хинт | `scene/import_dagor_composite.py` + `import_composite.py` | `actor` уже не является MH-authority; материализатор создаёт каноническое пустое определение `ACTOR_PLACEHOLDERS` |
| Приём p2 через типизированный профиль | `_dag4blend_profile` | Работает через `mh4blend.profile` + существующий `.placement` |

Не хватает **оркестрации публикации и перепривязки**, а не разбора сцены.

### Границы маршрута, которые нельзя обойти

dag4blend разбирает `.composit.blk` своим списком `separate_by`
(`prog/tools/dag4blend/cmp/cmp_import.py`) и кладёт распознанное в
`dagorprops` на Empty. Через этот маршрут **физически доезжает**:

```text
place_type:i, placeOnCollision:b, ignoreParentInstSeed:b,
rot_*/offset_*/scale/yScale:p2, include
```

и **теряется самим dag4blend, до MH**:

```text
aboveHt:r, useCollisionNormal:b, quantizeTm:b, label:t, colors, require,
xScale, snake_case-алиасы (place_on_collision, use_collision_norm)
```

Для потерянного MH делать нечего. По корпусу (26 089 файлов, отчёт
`reference_notes/dagor_corpus_inventory_20260828.md`) это `aboveHt` 14 файлов,
`useCollisionNormal` 8, `quantizeTm` 3; `label`, `colors`, `require` — ноль.

## 1. Четыре блокера — снять

Каждый начинается с failing-теста на текущем `origin/main`, вывод которого
попадает в квитанцию (инвариант о красном прогоне).

### 1.1 Пустой random-вариант

`ent{name:t=""; weight:r=2}` — легальная конструкция Dagor: в `loadAddEnt`
пустой вариант кладётся как `Obj` с `ent == nullptr` и участвует в рулетке
наравне с остальными. Идиома «здесь с некоторой вероятностью не будет ничего».

Сейчас конвертер падает:

```python
option_collection = option_obj.instance_collection
if option_collection is None:
    _raise("MH_E_COMPOSITE_GRAMMAR", ...,
           "dag4blend random option requires explicit resource collection")
```

Должен давать `RandomOption(kind="empty", weight=N, resource=None)`.

Семантика Dagor, которую нужно воспроизвести точно:

- пустой вариант сохраняется, **только если у того же узла есть хотя бы один
  настоящий вариант**; узел, у которого все варианты пустые, не порождает
  ничего и его `entList` очищается;
- вес пустого варианта участвует в нормализации наравне с остальными.

**Грамматика не меняется** — `kind: "empty"` в `_OPTION_KINDS` уже есть.
Это дефект одного конвертера.

Дополнительно: посчитать по корпусу число файлов с пустым `ent` — в
инвентаризации такой строки нет, а она определяет масштаб. Результат — в
квитанцию.

### 1.2 Перепривязка внешних placements

Симптом owner: рядом с legacy-коллекцией уже существует
`<name>.composite`, но Empty продолжает инстансировать старую dag4blend
коллекцию. Строгий closure exporter справедливо видит unmanaged dependency и
блокирует экспорт.

Нужна карта `логическое имя композита → исходная dag4blend Collection`,
построенная конвертером, и перепривязка по ней:

- меняются **только внешние** объекты рабочей сцены;
- объекты внутри сконвертированных composite-коллекций и внутри `random.*`
  хелперов **не трогаются**;
- legacy-определения и содержимое служебных сцен остаются нетронутыми как
  migration source;
- автоматического удаления legacy нет.

### 1.3 Усыновление мешей и порядок публикации

dag4blend mesh-коллекции остаются unmanaged. Пометить их флагом нельзя —
они обязаны сначала пройти настоящий MH FBX/material export, который и
ставит managed-метки.

Порядок публикации — dependency-first:

```text
materials → meshes → nested composites → root composite
```

Инвариант: сбой поздней стадии оставляет валидный замкнутый префикс, но
**никогда** опубликованный composite, ссылающийся на неопубликованный payload.
Операция безопасно повторяется после исправления ошибки.

Преflight выполняется реальными писателями (`prepare_fbx_collection`,
material writer) до любой записи.

### 1.4 `gameObj` → placeholder

Owner-решение: **все** `gameObj` становятся placeholder'ами. Узел сохраняет
имя и трансформ, в UE5 не порождает ни актора, ни кода, и при обратном
экспорте восстанавливается с теми же координатами и именем. Данные не
теряются, лишних сущностей в UE5 не появляется.

Это касается всех `gameObj` без разбора: `dummy_pivot` (центр координат сцены,
плейсхолдер для привязки в Dagor Editor), `loot_*` (точки спавна),
`envi_probe_box` и прочие. Реестр ролей `gameObj` **не нужен** — правило одно.

Blender-сторона к этому уже близка: `actor` считается транспортным хинтом, а
материализатор создаёт каноническое пустое определение `ACTOR_PLACEHOLDERS`.
Исполнитель обязан **установить тестом**, что происходит на UE-стороне с
`actor`-листом без записи в ActorClassRegistry, и только потом решать, нужна
ли там правка. Если существующий `PlanViewPlaceholder` уже даёт нужное
поведение — правки не нужно, нужен закрепляющий тест.

По корпусу: 3674 файла с `gameObj`, 11 880 вхождений, 386 различных имён.
Единое правило — единственное, что здесь масштабируется.

## 2. Два носителя — добавить, не исполнять

Оба поля опциональны и опускаются при дефолте, поэтому существующие
`.composite` остаются байт-идентичными. Резолвер, layout-подпись и
golden-векторы **не затрагиваются**: это метаданные источника, они входят
только в source/closure hash.

### 2.1 `placement` — носитель `place_type`

Owner-политика, три строки:

```text
импорт из CDK   → эффективное значение сохраняется в .composite
UE5             → никогда не применяется, игнорируется
запись из UE5   → блок placement опускается (эквивалент place_type=0)
```

То есть значение переживает пассивный round-trip и обнуляется при активном
редактировании из UE5. MH никогда не рассуждает о семантике прижатия.

Формат — как в документе 12 §1: опциональный объект узла с обязательным
`mode` из закрытого множества
`pivot | pivot_normal | three_point | foundation | water | pivot_collision`.
Отсутствие блока = «не прижимать» = `place_type:i=0`. Значение вне `0…6`
блокирует `MH_E_COMPOSITE_GRAMMAR`.

`placeOnCollision:b=yes` без явного `place_type` → `mode: pivot`. Явный
`place_type` перебивает флаг (документ 12 §2.10).

**Что установить эмпирически, а не предположить.** В Dagor `place_type`
наследуется от объемлющего блока на один текстовый уровень (документ 12 §2.9).
Разрешает ли это наследование сам dag4blend, или он кладёт в `dagorprops`
только то, что написано в самом узле, — по коду не следует однозначно, потому
что корневые свойства композита лежат вне любого `node{}`. Исполнитель
проверяет это на фикстуре 1 из инвентаризации
(`normandy_vernacular_debris_wood.composit.blk`: корневой `placeOnCollision:b=no`
и `aboveHt:r=2`, оба прямых узла без локальных контролей) и фиксирует
результат в квитанции. Если dag4blend наследование не разрешает — разрешает
mh4blend по иерархии Empty; если разрешает — mh4blend берёт значение как есть.

`trace_start_above_cm` в этом срезе **не вводится**: `aboveHt` теряется
dag4blend'ом, а прижатия не будет.

### 2.2 `appearance_seed_boundary` — носитель `ignoreParentInstSeed`

Сейчас теряется молча. По корпусу 190 файлов, 660 вхождений; через dag4blend
доезжает целым. Это тот флаг, который в V5-S6.3 станет границей сида покраски
и **будет реально работать**.

В этом срезе — **только носитель**: опциональный bool узла, дефолт `false`,
опускается когда `false`, потребителя нет. `useParentInstSeed` по корпусу ноль
вхождений; принимается как явный `false`, отдельной работы не требует.

## 3. Что не должно блокировать

`label:t`, `require{}`, `colors{}` — **ноль вхождений во всём корпусе** и,
сверх того, все три теряются самим dag4blend до MH. Останавливать на них
импорт не нужно ни в каком виде. Если конструкция всё же дойдёт до MH —
drop с `MH_W_DAGOR_CONSTRUCT_DROPPED`, называющим NodePath и конструкцию.

Отдельно: `require` остаётся **никогда не исполняемым**. Это topology
semantics; исполнение потребовало бы входа в резолвер и в подпись.

---

## 4. Что остаётся заблокированным — но с внятной диагностикой

**Inline p2 без типизированного профиля.** Решение по `OPEN-V5-15` не
принято, временное правило — блокировка. В этом срезе блокировка сохраняется,
но диагностика обязана называть NodePath **и перечислять конкретные
параметры**, которые её вызвали, чтобы художник знал, что именно выносить.
По корпусу 453 файла, в mall 6; доминирует одиночный `rot_y` (365 файлов).

**Dagor `prefab`.** Fail-closed по умолчанию с явным opt-in
`Allow Prefab as Mesh (Lossy)`. При включении — публикация как видимого
StaticMesh плюс warning о том, что collision/gameplay-семантика не
сохраняется. По корпусу 807 файлов, в mall ноль.

## 5. Чего не брать из внешнего overlay-патча

Дизайн внешнего патча в основном совпадает с этим срезом и был источником
пунктов 1.1–1.3. Не берётся следующее:

- **Механика доставки.** Патч приезжает Python-скриптом, правящим рабочую
  копию, база запинена на `7b46df5` и разъедется сразу после merge PR #29.
  Скрипт не применять. Срез реализуется от свежего `main` обычным порядком:
  ветка, PR, квитанция, owner merge.
- **Жёсткий блок на `place_type` и `ignoreParentInstSeed`.** Патч
  останавливает мост на них. Owner-решение — сохранять, а не блокировать
  (см. §2). Блокировка закрыла бы 1710 и 190 файлов корпуса соответственно.
- **Блок на `label`/`require`/`colors`** — см. §3.
- **`gameObj` как «actor token + placeholder»** в прежнем виде — заменяется
  единым правилом §1.4.

## 6. Acceptance

1. **Красные прогоны до изменений.** Для каждого из 1.1–1.4 — failing-тест на
   `origin/main` с приложенным выводом. Без него изменение не является
   исправлением дефекта.
2. **Пустой вариант.** Композит с `ent{name:t=""; weight:r=2}` рядом с
   реальным вариантом импортируется; вес участвует в нормализации; узел, у
   которого все варианты пустые, не порождает ничего.
3. **End-to-end.** Реальный композит из CDK, импортированный dag4blend
   (`Recursive/With dags/With lods` включены), проходит весь маршрут до
   `.material` + `.mesh.fbx` + `.composite` без ручного вмешательства.
   Фикстура — из `fixture_sources/`, не синтетическая.
4. **Relink.** Внешние placements переключены на managed-определения; объекты
   внутри сконвертированных коллекций и `random.*` хелперов **не изменены**;
   legacy-коллекции существуют и байт-идентичны.
5. **Порядок публикации.** Инструментированный тест фиксирует
   `materials → meshes → nested composites → root`. Инъекция сбоя на поздней
   стадии оставляет замкнутый префикс и **ни одного** опубликованного
   composite со ссылкой на неопубликованный payload. Повтор после исправления
   проходит.
6. **Носители.** Композит с `place_type:i=3` и `ignoreParentInstSeed:b=yes`
   импортируется; оба значения присутствуют в канонических байтах
   `.composite`; мировые матрицы и поведение UE **байт-идентичны** случаю без
   них. Запись композита, инициированная из UE5, опускает блок `placement`.
7. **Наследование.** Результат проверки из §2.1 зафиксирован в квитанции с
   указанием, какая сторона разрешает наследование.
8. **`gameObj`.** Композит с `dummy_pivot` и с одним `loot_*` импортируется;
   ни один актор в UE не создаётся; имена и трансформы сохранены и
   восстанавливаются при обратном экспорте.
9. **Не блокирует.** Композит с `label`/`colors` (синтетическая фикстура,
   в корпусе таких нет) импортируется с warning, а не с отказом.
10. **Диагностика.** Композит с inline p2 без профиля даёт отказ, называющий
    NodePath и конкретные параметры.
11. **Регрессия.** Существующие golden-векторы, `ResolvedSignature`, choices,
    samples и world transforms **байт-идентичны** состоянию до среза.
    Обычные `Export Composite` и `Export Composite Include All Stuff`
    остаются строгими и скрытой конвертации не выполняют.
12. Python + Blender suite, оба unity-гейта, packaged smoke.

## 7. Вне scope

- **Shared definition cache** — отдельный кандидат
  (`proposals/shared_composite_preview_cache.md`).
