## Выполнено

### Общий контракт и diagnostics

1. Материал имеет закрытую grammar: обязательный `class` с опциональными
   `twosided`, `textures` (`tex0`–`tex15`) и `params` (число или vector4), либо
   library-форма ровно из одного поля `library`. Unknown field/type/key
   блокируется `MH_E_MATERIAL_GRAMMAR`; static bools и `tex16support` не
   существуют.
2. Canonical JSON совпадает между Python и UE: UTF-8, LF, финальный LF,
   indent 2, нормативный порядок полей/ключей и float32 shortest round-trip.
   Общий fixture — `golden/material_v4_vectors.json`.
3. Введены и зарегистрированы
   `MH_E_NONCANONICAL_RESOURCE_NAME`, `MH_E_MATERIAL_GRAMMAR`,
   `MH_E_MATERIAL_NOT_ROUNDTRIPPABLE`,
   `MH_E_NONCANONICAL_TEXTURE_REFERENCE`,
   `MH_E_UNRESOLVED_TEXTURE_REFERENCE` и
   `MH_W_MANAGED_ASSET_LOCALLY_MODIFIED`. Legacy
   `MH_E_NON_ASCII_RESOURCE_NAME` удалён из registry/call sites/golden.
   Итоговый Python registry: `40 E / 17 W`.
4. `_temporary_lod_node_names` теперь возвращает
   `MHValidationError(MH_E_INVALID_LOD_HIERARCHY)`, не голый `ValueError`, без
   изменения fail-closed семантики S1.

### Blender/Python

1. Реализованы strict reader/writer Material v4 и отдельная
   `Material.mh4blend` property group с UI для class/library, texture slots и
   scalar/vector parameters. Старые dag4blend `is_proxy`/`proxy_path`/`sides`
   и v2 material-механика не участвуют.
2. Texture reference — только extensionless canonical logical name. Resolver
   напрямую сканирует всё source-дерево по ResourceKey `texture:<name>`,
   применяет нормативный allowlist extensions и блокирует unresolved,
   case-near либо same-kind duplicate без выбора победителя.
3. Reader сначала preflight/resolves/loads все зависимости и только затем
   меняет Blender material state. Writer находит единственный существующий
   `<name>.material` по всему source-дереву; missing создаёт в выбранной папке,
   duplicate/case variant блокирует.
4. Запись всегда sibling tmp → exact/semantic read-back → `os.replace`.
   Writer не делает diff. FBX export при включённой опции preflight'ит и
   публикует все уникальные затронутые материалы до FBX commit.

### UE 5.7 Editor plugin

1. Добавлены Editor-only Material protocol/importer/publisher/Adopt UI и
   `UMHMaterialSourceData`. Parent registries резолвятся строго как
   `<master_root>/<class>` и `<library_root>/<name>` без префиксов и без
   fallback.
2. Import выполняет полный in-place apply. Library apply очищает scalar,
   vector, texture, base/static overrides и reparent'ит к актуальному library
   registry asset. Texture dependencies принимаются только из текущего import
   task; source BLAKE3 сверяется с resolver generation до и после task, texture
   явно сохраняется и reload-проверяется.
3. Material source guard выполняется после dependency/probe preflight, но до
   load/create/register/mutation actual MIC. Race не оставляет новый package,
   Asset Registry ghost либо изменённый existing MI/receipt.
4. Applied state коммитится только после apply, compilation, actual-MI extract
   parity и успешного save. `SourceHash` хранит raw source hash, `AppliedHash`
   — hash canonical live extract. Перед source-wins overwrite локальная правка
   даёт `MH_W_MANAGED_ASSET_LOCALLY_MODIFIED`.
5. Решение `OPEN-V4-9` реализовано буквально: поле называется
   `AppliedParent` и хранит `class:<token>` либо `library:<name>`.
   `AppliedParent` receipt-only и нигде не читается для resolution. Import
   резолвит source JSON через текущие roots; Publish/Adopt делают live reverse
   lookup фактического parent MI. Asset Registry остаётся ровно с пятью тегами:
   `MH.Kind`, `MH.LogicalName`, `MH.SourcePath`, `MH.AppliedHash`, `MH.Managed`.
6. Publish делает live extract → canonical JSON → sibling tmp → read-back →
   atomic replace без diff. Library MI с любым override блокируется
   `MH_E_MATERIAL_NOT_ROUNDTRIPPABLE` до source write/receipt advancement.
   Adopt требует явные folder + canonical logical name и работает для class и
   library parent.

acceptance. Новых нормативных решений исполнитель не вводил.
