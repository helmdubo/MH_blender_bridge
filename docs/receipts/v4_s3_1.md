## Выполнено

1. Composite import больше не блокирует отсутствующий `mesh` или `composite`.
   Для placement создаётся `EMPTY` без data/instance content, с
   `empty_display_type = CUBE`, красным object color и custom properties
   `mh_composite_kind`, `mh_composite_resource` и
   `mh_unresolved_placement`.
2. Импорт возвращает зарегистрированный `MH_W_UNRESOLVED_PLACEMENT`; оператор
   Blender показывает его пользователю как `WARNING`. Итоговый diagnostics
   registry: `44 E / 11 W`.
3. Missing composite считается leaf только в Blender authoring closure.
   Existing self/ancestor cycle, noncanonical identity и ambiguous same-kind
   duplicates остаются fail-closed. Та же ambiguity-проверка выполняется
   writer'ом до atomic replace.
4. Writer допускает missing mesh/composite dependency и сохраняет lossless
   resource token. Publication по-прежнему выполняется через canonical encode,
   sibling tmp, read-back и `os.replace`; diff не вычисляется.
5. Для каждого placement импортированного Composite сохраняются canonical
   source-transform и точный снимок его Blender world-matrix. Пока matrix не
   менялась, Export использует source DTO и не теряет binary32 ULP при
   cm↔m round-trip; после изменения объекта snapshot инвалидируется и Export
   пишет live transform. Это закрывает byte-identical contract также для
   `children` отсутствующего узла.
6. После появления ранее отсутствовавшего source-файла свежий импорт в чистую
   сцену создаёт полноценный collection instance без warning и placeholder
   marker. Автоматическая мутация уже открытой сцены не вводилась.

## Acceptance-покрытие

- missing mesh и missing composite: красный cube-Empty, отсутствие content,
  warning, lossless kind/resource/name/tree;
- whole-file byte equality после import→export на проблемных binary32
  значениях (`-63530.69140625`), nonidentity quaternion/scale и nonidentity
  transformed child;
- изменение world-matrix child инвалидирует сохранённый DTO и публикует live
  transform;
- появление `.mesh.fbx`/`.composite` + свежий импорт даёт реальный instance;
- две same-kind зависимости с одинаковым logical name блокируют import без
  datablock delta и writer без изменения существующего target;
- искусственный сбой после создания unresolved placeholder откатывает полную
  дельту Blender datablocks;
- UI operator показывает `MH_W_UNRESOLVED_PLACEMENT`.
