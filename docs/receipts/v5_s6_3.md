## Реализовано

### H. Python reference + goldens

`mh.appearance:1`, 4 канала, поток на лист по пути границы (ближайший
предок с boundary, иначе корень размещения = имя root-композита),
RawU32 — авторитет, `unit = float32(raw·2⁻³²)` с задокументированным
edge (`raw ≥ 0xFFFFFF80` → 1.0f, не клампится). `AppearanceSignature`
blake3-160 канонического JSON `{v, stage, appearance_seed, channels,
boundaries(sorted UTF-8), leaves[{path, boundary, channels[raw]}]}`;
`PlacementSignature = blake3-160(resolved_sig ‖ appearance_sig)`.
Golden `golden/v5/appearance/appearance_1_vectors.json` (480 КБ, 77
векторов: 49 независимости сидов + 4 сценария границ × 7, включая
mixed c gameobj/empty без розыгрышей); rules-блок фиксирует контракт
дословно. Layout-goldens — sha256-доказательство неизменности.
21 новый pure-тест.

### G. UE

- Дуальный сид: `Seed` (serialized-имя прежнее, UI «Layout Seed»),
  `AppearanceSeed`, `bAutoAppearanceSeed`, авто-сид зеркалит layout в
  PostActorCreated/PostDuplicate/PostEditImport. **Миграция**: формула
  `MHMakeNodeRandomStream(Seed,"appearance").NextU32()` (bit-cast
  int32), материализуется один раз в PostLoad, маркер
  `bAppearanceSeedStored` (legacy-запись байт-идентична записи без
  свойств), dirty — в PostRegisterAllComponents (в PostLoad no-op).
  Красный defeated-baseline доказал нагрузку каждого гейта (8 failed).
- Appearance-стадия резолвера, отдельные `Plan.Appearance.Draws`,
  подписи; runtime-транспорт v2 (append-only, v1 читается): boundary
  доезжает до cooked/PIE — иначе пятисторонний паритет был бы ложью;
  `place_type` в транспорт по-прежнему не входит (ассерт разделён).
- Метаданные плана: `ParentResolvedNodeIndex` (pre-order checkf),
  `SelectedOptionIndex`, `OwningResolvedNodeIndex`,
  `AppearanceChannels[4]` — вне обоих прообразов (тест), проверены на
  GAZ-53.
- **Найден и исправлен спящий кросс-host дефект layout-прообраза**:
  UE писал `[  ]` для пустого массива против `[]` reference — любой
  композит без random-узлов расходился бы подписями (ушёл бы в S7).
  Утверждено Lead: golden не менялись, все layout-паритеты зелёные,
  планы с ≥1 decision байт-идентичны до/после.
