# Квитанция — осевая конверсия inline p2 (перевёрнутый чайник)

Дата: 2026-08-31
Ветка: `fix/inline-p2-axis-conversion`
Исполнитель среза: Lead
Статус: **READY FOR OWNER FIELD TEST (переэкспорт композитов + Import Changed)**

## 1. Полевой дефект

После осевого фикса мешей предметы с inline p2 rotation-спредом
(чайник, консервный нож, кружки) лежат перевёрнутыми и тонут в столах:
Sampled TRS показывает кватернион с Y-компонентой — разворот-спред
`rot_y:p2` (дагоровская **вертикаль**) применялся вокруг UE **Y**
(горизонтали), опрокидывая предмет вместо азимутального разворота.
Найдено owner'ом по Outliner overlay (deviation 180 на index[1]).

## 2. Диагноз

Адаптер конвертирует матрицы узлов сопряжением Dagor(Y-up, LH) →
Blender(Z-up, RH) (`_DAGOR_TO_BLENDER`), но оси inline p2 маппил
напрямую x→[0], y→[1], z→[2] — без пермутации, знаков хиральности и
конверсии единиц. Скрыто до сих пор: до осевого меш-фикса всё поле было
повернуто согласованно, а до inline-ревизии p2 вообще блокировался.

## 3. Реализация

`import_dagor_composite.py::_dag4blend_inline_placement` — то же
сопряжение, что и для матриц узлов:

| Dagor p2 | placement-v1 (UE Z-up) |
|---|---|
| `rot_x (θ)` | `rotation_deg[0]`, base **−θ** |
| `rot_z (θ)` | `rotation_deg[1]`, base **+θ** |
| `rot_y (θ)` — вертикаль | `rotation_deg[2]`, base **−θ** |
| `offset_x (м)` | `offset_cm[0]` ×100 |
| `offset_z (м)` | `offset_cm[1]`, base **−**, ×100 |
| `offset_y (м)` — вертикаль | `offset_cm[2]` ×100 |
| `scale` / `yScale` | `uniform_scale` / `vertical_scale` (как было) |

Deviation — всегда неотрицательная величина (не меняет знак). Заодно
закрыта потерянная конверсия единиц оффсетов (метры Dagor → см,
×100 — прежде оффсеты приезжали в 100 раз меньше и были незаметны).

UE-сторона не менялась (резолвер применяет placement-оси корректно).
Wire-формат не менялся. Нормативное дополнение — QUESTIONS.md
OPEN-V5-15. Аддон 0.13.0.
