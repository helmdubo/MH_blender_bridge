## Реализация

### Команды и source closure

1. Существующая `Export Composite` публикует только выбранный root, но теперь
   использует тот же полный closure-preflight, что и batch-команды.
2. `Export Composite + Composite Closure` публикует root и все вложенные
   composites. Mesh/material payloads не публикуются, но остаются членами
   source closure и обязаны иметь уникальный managed source.
3. `Export Composite Include All Stuff` дополнительно публикует загруженные
   полные managed meshes и materials. Texture payloads команда не создаёт и
   не копирует.
4. Walker обходит всех детей и все options всех random-узлов, включая
   zero-weight/невыбранные варианты. На том же графе выполняется cycle
   detection. Seed/InstanceSeed отсутствует в API, operators и panels.
5. Для каждой зависимости сохраняется referring composite. Missing excluded
   mesh/material выдаёт `MH_E_RESOURCE_NOT_FOUND` с ResourceKey, referrer и
   точной командой `Export Composite Include All Stuff`; unmanaged и
   ambiguous сохраняют соответствующие ratified коды.

### Preflight, staging и публикация

1. До staging валидируются typed bindings, managed authority, duplicate
   physical identity, канонические source bytes, profile identity, material
   texture references и physical containment внутри Source Root.
2. Nested unmanaged binding блокируется до DFS. Existing unloaded managed
   source читается и переиспользуется byte-for-byte; replace для него не
   выполняется.
3. Каждый payload замыкания проходит staging во внешнем temp-каталоге и
   read-back. Mesh дополнительно проходит структурный FBX read-back.
   Preflight/staging error не создаёт и не меняет source-файлы.
4. Порядок плана: placement profiles → materials → meshes → composite
   postorder → root last. Replace получает только `action=publish`; любой
   опубликованный префикс dependency-closed.
5. Placement profile не имеет отдельного Blender datablock/carrier bytes.
   Единственный authoring/publish путь остаётся общим
   `core/placement_publication.py` у Dagor importer. S4 не создаёт второй
   collision policy: профиль closure должен уже существовать как уникальный
   canonical managed source, затем staging/read-back проверяет и переиспользует
   его без перезаписи.
6. Textures — только closure/preflight зависимости через
   `resolve_texture_reference`. Outside-root/ambiguous/missing сохраняют точный
   texture-код, ResourceKey, referrer и corrective command
   `Copy All Textures to Project, then Remap All Texture Paths`.
7. Blender не выпускает UE self-publish token и не создаёт marker/lock/
   sentinel/transaction manifest в Source Root. Это внешний writer по
   ratified §13.9; согласованность промежуточного состояния обеспечивает
   publish order.
8. После первого успешного replace soft failure повышается до
   `MH_E_PARTIAL_PUBLISH` с точными ordered `published`/`unpublished` sets.
   Rollback не обещается; восстановление — VCS.

### Crash/failure acceptance на каждой границе

Отдельный Blender-free publisher тестируется на каждой границе каждого из
трёх replace (`material:leaf`, `static_mesh:body`, `composite:root`):

- injected exception `before_replace` и `after_replace`, 6 комбинаций;
- реальный subprocess crash `before_replace` и `after_replace`, 6 комбинаций;
- injected directory-fsync failure после фактического `os.replace`.

До первого replace исходная ошибка проходит без ложного partial-report. После
replace observer фиксирует ресурс опубликованным до directory fsync, поэтому
даже эта ошибка даёт точные множества. Subprocess-проверки читают диск после
exit 91/92 и подтверждают только полный dependency-closed prefix. Root ни в
одном сценарии не появляется раньше зависимостей.
