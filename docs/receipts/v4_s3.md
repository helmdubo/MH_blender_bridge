## Выполненная ориентация

1. Три независимых read-only прохода разложили:
   - Blender mesh import stages 0–4, parse-truth, material slot indices,
     staging, rollback journal и один undo-step;
   - Blender Composite codec/import/export и integration поверх общего
     mesh-resource importer;
   - UE Composite protocol/asset/compiler/import/publish/settings и Automation.
2. Подтверждён штатный seam Blender 4.5.12:
   `io_scene_fbx.parse_fbx.parse()` для stage 0 и прямой
   `io_scene_fbx.import_fbx.load()` с explicit settings для stage 2. Прямой
   loader не создаёт вложенный operator undo; import идёт в active layer
   collection.
3. Ordered FBX connections Material → Model являются истиной slot order.
   Geometry name с `.001`, уже записанный exporter'ом из disposable Mesh copy,
   является parse-truth, не Blender autorename. Успешный import обязан
   сохранить буквальные Model/Geometry names; любое дополнительное искажение
   (`.002` и т.п.) блокируется и откатывается. Placeholder Material/Image из
   loader delta не переживают операцию.
4. Сформирована граница общего mesh API для оператора и Composite importer:
   pure parse plan → aggregate occupancy/material preflight → apply в caller
   transaction → restructure/report. Composite closure должен импортировать
   каждое уникальное mesh-definition один раз и размещать instances поверх
   него.

## Нормативные блокеры

### `OPEN-V4-10`

08 §6 не задаёт закрытую grammar Composite и transform/canonical contract,
необходимые для байт-совместимых Blender/UE writers, AppliedHash и одинаковой
компиляции размещений. Старый transform codec не может быть использован:
ссылающийся на него schema superseded. Также требуется подтвердить границу
actor registry и UE-only applied-state warning.

### `OPEN-V4-11`

Collision name `UCX_*_cls_phys|trace` одновременно матчится на два разных
режима таблицы 08 §4; precedence/reject не определён. До решения общий
classifier не выбирает режим автоматически.

Оба вопроса оформлены в `docs/QUESTIONS.md` с временными fail-closed правилами.
Composite surfaces остаются существующими `MH_E_INVALID_COMPOSITE` stubs;
production Composite bytes не интерпретировались.
