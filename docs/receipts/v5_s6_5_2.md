## 3. Реализация editor diff

`AMHCompositeActor::RebuildPlacement` пробует incremental compiler
только для настоящего layout reseed: старый plan валиден, seed изменился,
`EMHCompositeSeedEffect != None`. Любое отклонение admission возвращает
управление неизменённому full compiler; отдельная точка создания
компонентов не добавлена.

Admission выполняется полностью до endpoint lookup и мутации:

- точные counts и порядок tracked handles/leaves/derived;
- owner, exact component class, registration, один canonical MH tag;
- attachment parent и absolute transform flags;
- прежний appearance CPD совпадает с previous plan;
- живой mesh endpoint имеет canonical generated path;
- живой child-actor class совпадает с уже загруженной записью registry;
- top-level NodePath и RootNodeIndex не расходятся.

После admission планы сопоставляются по leaf `Origin` (canonical
NodePath). Для стабильной тройки `(NodePath, Kind, Resource)` сохраняется
тот же объект компонента; меняются только world transform и CPD, если
байты соответствующего значения действительно изменились. Новый или
изменившийся leaf проходит штатный `PlanViewNew`; исчезнувший уходит в
существующий `DestroyMHRetiredComponents`. Endpoint загружается только
для replacement leaf. Handles сохраняются по authored root path.

При искусственном рассинхроне fast-path не чинит состояние частично:
возвращает `false` до мутации, actor учитывает один full fallback, а
существующий orphan-union/full compiler восстанавливает корректный вид.
Новый diagnostic code не вводился.

## 5. Dagor reference

Проверены документация
[Asset Viewer Composite Editor](https://gaijinentertainment.github.io/DagorEngine/dagor-tools/asset-viewer/asset-viewer-comp-editor/asset_viewer_comp_editor.html)
и исходный
[`compositMgrService.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/75723669297e48e200a0dc67b18c1629e0975daf/prog/tools/sceneTools/daEditorX/services/compositMgr/compositMgrService.cpp).

Применимый принцип Dagor — сохранять живые sub-entity и не повторять
работу для seed-независимого поддерева. Он реализован здесь на уровне
UE placement components. Архитектура целиком не переносилась:

- Dagor держит общую parsed definition в `CompositEntityPool` и
  оперирует живыми pooled sub-entity;
- `seedAffectsResult()` позволяет не регенерировать seed-независимый
  уровень, а generated уровень освобождает/создаёт свои sub-entity;
- Mimir обязан сначала получить полный immutable
  `FMHResolvedCompositePlan` и канонические подписи, после чего имеет
  право мутировать Actor Components.

Сама документация предупреждает о performance impact редактора на
больших nested composites. Поэтому Dagor не является доказательством
возможности пропустить Mimir plan/signature authority.

   внутри Actor/Component lifecycle.
