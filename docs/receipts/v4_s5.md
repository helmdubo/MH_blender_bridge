# Квитанция Source Protocol v4 — S5 UE StaticMesh importer

Статус: **STOP ДО OWNER-РЕШЕНИЙ `OPEN-V4-20`–`OPEN-V4-22`**.

## База и ветка

- owner-base: `origin/main` = `0bf1626`;
- ветка: `v4/s5-static-mesh`, создана непосредственно от `origin/main`;
- 08 и 09 перечитаны полностью, включая новый 08 §6.1;
- production-код, `reference/`, `golden/` и UE Engine не изменялись.

## Выполненный read-only аудит

1. Direct FBX SDK уже подключён только к editor-module и имеет рабочий
   axis-probe, но production `FMHSceneIR`, `IMHGeometryTranslator`, build plan,
   builder, `UMHStaticMeshImportData`, mesh-importer и `mh.fbxdump:4`
   отсутствуют.
2. Определены seams реализации: recursive SDK parse с evaluated global
   transforms → зеркальный C++ classifier → pre-resolved slot plan → полный
   in-place rebuild LOD/BodySetup/sockets/slots → compile/save → receipt.
3. Project Index уже поддерживает binary `static_mesh`, deterministic path,
   applied/stale projection и тождество шестых tags
   `MH.AppliedHash == MH.SourceHash`; отсутствуют static-mesh carrier,
   slot-dependency extraction и mesh execution pass.
4. Зафиксированы обязательные интеграционные условия: parse FBX из стабильного
   snapshot (не повторно открытых изменившихся bytes), точный role `slot`,
   `MH_E_UNRESOLVED_MATERIAL_REFERENCE` для missing material, materials до
   meshes, mesh до composites, orphan-event после успешного receipt save и до
   GeneratedAssets refresh.
5. Составлена acceptance-матрица: SceneIR/classifier, slot closure, все dense
   LOD, несколько render nodes, collision modes, sockets, exact MI bindings,
   тот же UObject при полном rebuild, NO_CHANGE, save/reload receipt и exact-six
   tags, local modification, v4 dump и plain FBX без MH metadata.

## Нормативные блокеры

- `OPEN-V4-20`: не определены типы/домены `RecipeHash`, `AppliedAssetHash`,
  `LastSuccessfulTransaction`, canonical live-asset fingerprint и cadence
  local-edit detection/forced reimport. Это напрямую блокирует обязательный
  `MH_W_MANAGED_STATIC_MESH_LOCALLY_MODIFIED`.
- `OPEN-V4-21`: не определены публичное имя `UStaticMeshSocket` после
  `SOCKET_` и collision shape/cooking policy для `UCX_*`/`_cls_*`.
- `OPEN-V4-22`: transport-level FBX failures не имеют зарегистрированного
  машинного кода; старый probe использует незарегистрированный
  `MH_E_GEOMETRY_SOURCE_MISMATCH`.

До решений нельзя построить полный обязательный asset, корректный receipt и
negative diagnostics, не изобретая новый норматив. Частичная production-
реализация намеренно не начата.
