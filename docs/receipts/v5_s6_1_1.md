## Реализовано

### A. LOD material union + cls + `.00N` (Python writer/reader)

- `MH_E_LOD_SLOT_NOT_IN_BASE` retired (код остаётся в реестре, не
  выбрасывается). `lod_ordered_material_union`: LOD0-слоты в порядке
  первого появления → новые слоты LOD1 → LOD2 … → хвост слотов
  только-non-render узлов (UCX) в порядке узлов.
- Распознавание даговской коллизии **material-first**: реальные имена
  узлов (`Cube.774`, `gaz53_a_body.lod01 cls phys.001`) не подчиняются
  доковому паттерну `*_cls_phys*`; надёжный признак — токен `cls` через
  `[ ._]` и/или техническая покраска (материал `cls` / shader
  `gi_black`). Исключение из render payload с
  `MH_W_DAGOR_CONSTRUCT_DROPPED` (узлы + материалы). `UCX_`/`SOCKET_`
  UE-конвенция сохранена.
- `.00N`: материал `X.00N` сливается в `X` при float32-эквивалентном
  dagormat-fingerprint, иначе `MH_E_AMBIGUOUS_RESOURCE_NAME` с именем
  разошедшегося поля; группировка file-wide (обоснование —
  `_duplicate_group`). Имена mesh-объектов не нормализуются (FBX Model
  names не канонизируются, ресурс уже берётся из `.lods`-имени).
- Red→green: pure mesh_nodes 3F→25P; Blender export_fbx 14F→43P.

### B. Admission + mixed-root + save/reopen (Python adapter)

- Структурный completeness admission: пустая nested dagor-коллекция →
  reuse непустого source или отказ; пустой root — отказ во всех режимах;
  root_only без требований к геометрии.
- **Mixed-root дыра закрыта** (P0 аудита): красный тест доказал, что
  native MH-ридер превращал legacy gameobj-коллекцию в исполняемый
  `{"kind":"actor"}`; теперь `MH_E_INVALID_RESOURCE_SOURCE`
  «mixed scene representation». Интерпретация Dagor осталась только в
  двух разрешённых читателях (адаптер, mesh-input планировщика).
- **Save/reopen гейт поймал настоящий дефект**: адаптер читал
  depsgraph-зеркало `Object.matrix_local`; несвязанная в view layer
  definition-коллекция молча экспортировала identity-трансформы, та же
  сцена после reopen давала другие байты. Исправлено чтением авторских
  `matrix_parent_inverse @ matrix_basis` + постоянная регрессия
  независимости от evaluation.
- Path (a) — Legacy-баннер в module docstring и в UI
  (`Import Dagor Composite (Legacy)`); поведение не менялось.

### C. UE per-LOD section materials

- Красный baseline вскрыл **два уже существовавших дефекта**:
  (1) `SectionInfoMap` не записывался вовсе — LOD с иным
  составом/порядком слотов молча рендерился неверными материалами
  (секция N → материал N); (2) `SetNumSourceModels` оставлял активной
  авто-редукцию LOD1+ — билд **выбрасывал авторские LOD1+** и подменял
  их 50%-декимацией LOD0. Оба исправлены (`SectionInfoMap` +
  `OriginalSectionInfoMap` на LOD/секцию; `ResetReductionSetting` +
  ассерты треугольников/секций каждого LOD).
- Union в `MHClassifySceneIR`: слот принадлежит наименьшему LOD,
  который его использует; порядок — чистая функция байтов FBX.
- `MHStaticMeshImporterVersion` 2→3: существующие managed-меши
  перестроятся один раз при следующем скане и получат настоящие
  авторские LOD и корректные секции (видимый и желаемый эффект).
- Отказ вместо позиционного fallback для узла без материала при
  непустом union (`MH_E_UNRESOLVED_MATERIAL_REFERENCE`).

### Lead-интеграция

- Сверка порядка union Python ↔ UE: семантика идентична
  («слот у наименьшего использующего LOD»). Единственная зафиксированная
  асимметрия — «хвост» Python-union (слоты только UCX-узлов), которого
  нет в UE `MaterialNames`; реального контента с кейсом нет (в Dagor
  нет UCX); унификация — в S6.1.2 вместе с формализацией коллизий.
- Прокладка writer-warnings в публичный отчёт/exception
  (`publish_dag4blend_composite_collection` собирает
  `row.prepared.warnings`); регрессия
  `test_writer_drop_warnings_reach_the_public_report`.
- Doc 15 §2.4 приведён к owner-формулировке (reuse при непустом source).
