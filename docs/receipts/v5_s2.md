## Выполнено

### Python и общие canonical-векторы

1. `.composite` полностью переведён на v5: первое поле `"v": 5`, закрытая
   grammar, parent-local T/R/S, `random` с ordered `options`, `empty`, optional
   `profile`, duplicate-key reject и canonical UTF-8/LF writer.
2. Файл без `v` блокируется кодом `MH_E_COMPOSITE_LEGACY_GENERATION` и точным
   сообщением «файл прежнего поколения: удалите и переэкспортируйте»; неверная
   версия — `MH_E_UNKNOWN_SCHEMA_VERSION`. Ни dual-read, ни fallback нет.
3. Добавлен строгий `.placement` v1 codec (`kind=placement_profile`) с
   ратифицированными парами `[base,deviation]`, closed grammar и проверками
   finite/non-negative/strictly-positive scale range.
4. `golden/v5/source_protocol_v5_codec_vectors.json` — общая Python/C++ истина
   для positive/negative composite и placement bytes, duplicate keys,
   missing/wrong version и 8-ULP/shear predicate. Повторная генерация
   байт-идентична.
5. Общий representability predicate сравнивает все 16 matrix elements во
   float32 с допуском 8 ULP; non-finite и shear блокируются. Отрицательный
   ненулевой scale допускается, если проходит reconstruction predicate.

### UE codecs, carrier и индекс

1. C++ parser/writer читает тот же codec golden, проверяет exact canonical
   bytes, duplicate keys и все fail-closed vectors. V4 parser/writer API
   физически заменён V5 API.
2. Placement profiles инлайнятся в `UMHCompositeAsset` как applied state.
   Отдельного UAsset, generated path и седьмого Asset Registry tag нет.
3. Source index сканирует `.placement` как `placement_profile` и создаёт ровно
   ребро `composite → placement_profile` с role `profile`; importer разрешает,
   парсит и атомарно применяет profile carrier вместе с composite.
4. Compiler/Build/Edit/Break переведены с document-world на parent-local
   composition. Preflight проверяет accumulated matrices общим 8-ULP
   predicate до component/actor/source mutation. Probe `parent 100 + child
   local 25 = world 125` и shear reject без mutation закреплены Automation.
5. Source closure и resolved plan имеют разные типы/API. Closure seed-free,
   обходит все random options и ловит цикл даже в zero-weight невыбранной
   option. Random/profile preview materialization остаётся fail-closed до S5.

### C++ `mh.random_stream:1`

1. Runtime implementation повторяет принятый S1 baseline: splitmix64, int32
   seed bit-cast, high-32 `next_u32`, `u32 * 2^-32`, ordered float64 weighted
   selection со строгим `>`, ровно один selection draw и отсутствие draw для
   отсутствующего profile-параметра.
2. Один resolver выдаёт decisions, draw trace, leaves, origins,
   SelectedDependencies, signature preimage и BLAKE3-160 ResolvedSignature.
   Component spawning внутри этого среза random не выбирает.
3. UE Automation напрямую читает `golden/v5/random_stream_1_vectors.json` и
   проверяет все frozen seeds, raw u64/u32, choices, profile samples, world
   T/R/S, dependencies, точные preimage bytes и signatures.
4. Во время gate найден и исправлен 1-ULP defect: C++ преждевременно сужал
   `parent.scale × local.translation`; теперь операнды расширяются до float64 и
   округляются в той же точке, что Python reference. Golden при этом не менялся.
