## Выполнено

### Python и общие canonical-векторы

1. `.composite` полностью переведён на v5: первое поле `"v": 5`, закрытая
   grammar, parent-local T/R/S, `random` с ordered `options`, `empty`, optional
   `profile`, duplicate-key reject и canonical UTF-8/LF writer.
2. Файл без `v` блокируется кодом `MH_E_COMPOSITE_LEGACY_GENERATION` и точным
   сообщением «файл прежнего поколения: удалите и переэкспортируйте»; неверная
   версия — `MH_E_UNKNOWN_SCHEMA_VERSION`. Ни dual-read, ни fallback нет.
3. Добавлен строгий `.placement` v1 codec (`kind=placement_profile`) с
   ратифицированными парами `[base,deviation]`, closed grammar и проверками
   finite/non-negative/strictly-positive scale range.
4. `golden/v5/source_protocol_v5_codec_vectors.json` — общая Python/C++ истина
   для positive/negative composite и placement bytes, duplicate keys,
   missing/wrong version и 8-ULP/shear predicate. Повторная генерация
   байт-идентична.
5. Общий representability predicate сравнивает все 16 matrix elements во
   float32 с допуском 8 ULP; non-finite и shear блокируются. Отрицательный
   ненулевой scale допускается, если проходит reconstruction predicate.

### UE codecs, carrier и индекс

1. C++ parser/writer читает тот же codec golden, проверяет exact canonical
   bytes, duplicate keys и все fail-closed vectors. V4 parser/writer API
   физически заменён V5 API.
2. Placement profiles инлайнятся в `UMHCompositeAsset` как applied state.
   Отдельного UAsset, generated path и седьмого Asset Registry tag нет.
3. Source index сканирует `.placement` как `placement_profile` и создаёт ровно
   ребро `composite → placement_profile` с role `profile`; importer разрешает,
   парсит и атомарно применяет profile carrier вместе с composite.
4. Каждый инлайненный `FMHPlacementProfile` хранит private editor-only
   `AppliedSourceHash` exact raw `.placement` bytes. Он отражён UProperty для
   package persistence, но исключён из wire JSON, canonical composite extract,
   `MH.AppliedHash`, шести Asset Registry tags и SQLite.
5. Pure-projection index профильную свежесть не изображает: после валидной
   правки `.placement` `GeneratedAssets.status` composite остаётся `applied`.
   Для otherwise-`NO_CHANGE` composite импортёр сначала читает индексное
   `profile`-ребро; только при его наличии загружает exact generated carrier,
   сравнивает полное множество `{LogicalName, AppliedSourceHash}` с raw hashes
   resolver и повышает mismatch/legacy-empty/duplicate до `REIMPORT`.
   Profile-free `NO_CHANGE` composite не загружается.
6. Import двухфазен: первый payload-save оставляет новые profile receipt
   markers пустыми; exact hashes продвигаются только финальным receipt-save.
   Ошибка между фазами гарантирует будущий `REIMPORT`, а не ложный
   `NO_CHANGE`.
7. Импорт сохраняет exact source bytes каждого инлайнимого profile и повторно
   читает те же пути перед первой UAsset-мутацией. Изменение/исчезновение
   profile после resolve блокируется `MH_E_SOURCE_INDEX_SNAPSHOT_CHANGED`;
   test hook подтверждает отсутствие ghost asset.
8. Recovery `missing|invalid|ambiguous → unique` симметрично возвращается к
   receipt comparison; source-only `.placement` не выдаёт phantom `CREATE`.
9. Compiler/Build/Edit/Break переведены с document-world на parent-local
   composition. Preflight проверяет accumulated matrices общим 8-ULP
   predicate до component/actor/source mutation. Probe `parent 100 + child
   local 25 = world 125` и shear reject без mutation закреплены Automation.
10. Source closure и resolved plan имеют разные типы/API. Closure seed-free,
   обходит все random options и ловит цикл даже в zero-weight невыбранной
   option. Random/profile preview materialization остаётся fail-closed до S5.

### C++ `mh.random_stream:1`

1. Runtime implementation повторяет принятый S1/S1.1 baseline: splitmix64, int32
   seed bit-cast, high-32 `next_u32`, `u32 * 2^-32`, ordered float64 weighted
   selection со строгим `>`, ровно один selection draw и отсутствие draw для
   отсутствующего profile-параметра.
2. По §13.8 каждый `random`-узел и каждый узел с `profile` открывает собственный
   поток: первые 8 байт BLAKE3-256 от UTF-8 canonical `NodePath` читаются как
   little-endian `uint64`, XOR с placement state и ровно один splitmix64 step.
   Random+profile делят один внутринодовый поток в порядке selection → profile;
   depth-first traversal больше не влияет на значения других NodePath.
3. Один resolver `mh.random_resolver:2` выдаёт decisions, draw trace, leaves, origins,
   SelectedDependencies, signature preimage и BLAKE3-160 ResolvedSignature.
   Component spawning внутри этого среза random не выбирает.
4. UE Automation напрямую читает `golden/v5/random_stream_1_vectors.json` и
   проверяет все frozen placement streams, все 21 node-stream vector
   (placement/path/mixed/initial states и draws), choices, profile samples,
   world T/R/S, dependencies, точные preimage bytes и signatures.
5. Во время исходного gate найден и исправлен 1-ULP defect: C++ преждевременно сужал
   `parent.scale × local.translation`; теперь операнды расширяются до float64 и
   округляются в той же точке, что Python reference. Golden при этом не менялся.
