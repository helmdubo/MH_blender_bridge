## Выполнено

### Typed Blender authority и Options UI

1. `Object.mh4blend` является единственной authority для `kind`, `weight`,
   `option_index` и `profile`. ID properties
   `mh_composite_kind`, `mh_random_weight`,
   `mh_random_option_index`, `mh_composite_profile` поддерживаются только
   как однонаправленное диагностическое зеркало; typed state всегда побеждает.
2. Random-node и options представлены Empty-объектами. Option resource задаётся
   `instance_collection`; weight/index/profile не протекают в resource
   Collection. Profile на option блокируется fail-closed.
3. Options UI реализует Add/Remove/Up/Down/weight. Reorder меняет explicit
   indices; missing/negative/duplicate index, invalid kind/weight и all-zero
   weights остаются наблюдаемыми и блокируют export без silent repair.
4. Option transform display-only и не влияет на canonical bytes. Ordinary
   children random-узла не смешиваются с options.
5. Явная materialization создаёт ровно четыре служебные сцены:
   `COMPOSITE`, `MESH`, `ACTOR_PLACEHOLDERS`, `TECH`; `TECH` не
   становится source authority.
6. Seed/InstanceSeed отсутствует в RNA, operators, panels и custom properties;
   static gate проверяет весь `addon/mh4blend`.

### Dagor→MH и placement profiles

1. Строгий Blender-free parser `*.composit.blk` сохраняет source order,
   explicit `name:type`, `ent`, implicit/explicit weight, raw 3×4 matrix,
   `include` и полную provenance.
2. Direct importer рекурсивно читает ordinary children и все random options,
   проверяет physical identity/ambiguity всего замыкания и оставляет missing
   definitions видимыми typed placeholders.
3. Dagor Y-up matrix переводится basis conjugation в Blender Z-up; local и
   composed-world matrices проходят 8-ULP float32 TRS predicate. Shear
   блокируется `MH_E_UNREPRESENTABLE_TRANSFORM` с causal ancestry,
   resource names и file/line/NodePath.
4. Уже импортированная dag4blend-сцена распознаёт random по helper Collection
   `random.*` или `type:t == "random"`. Weight cascade:
   `dagorprops['weight:r']` → ID `weight:r` → ровно `1`.
5. Options поднимаются из helper/`TECH_STUFF` в typed direct children;
   helper-данные не становятся MH authority.
6. `include` identity равен stem файла дословно. Неканоничный stem блокируется
   `MH_E_NONCANONICAL_RESOURCE_NAME`; lowercase/нормализация/генерация имени
   отсутствуют.
7. Include-профиль материализуется как canonical
   `<name>.placement` рядом с производимым composite. Глобальный preflight
   сравнивает canonical bytes: идентичный профиль переиспользуется без записи,
   divergent duplicate блокируется `MH_E_AMBIGUOUS_RESOURCE_NAME` с обоими
   путями.
8. Публикация профилей — последний finalizer общей Blender-транзакции:
   exact-byte revalidation выполняется перед первой записью, target-race
   блокируется, а ошибка публикации откатывает все Blender swaps. Сам
   `.composite` этим importer не публикуется.
9. Обычный Export Composite принимает только уникальный существующий
   canonical `.placement` и не перезаписывает его. Непереносимые
   dag4blend `p2/include` без typed profile authority блокируются lossless.

### Load modes, reuse/refresh и rollback

1. Placement tree строится полностью всегда. Режимы отличаются только
   геометрией:
   - `full-LOD`: полный §4.1;
   - `LOD0`: lod00 плюс коллизии/сокеты/группы и материалы;
   - `structure-only`: пустые stamped Collections без материалов.
2. `LOD0` и `structure-only` ставят `mh_incomplete_import = True`.
   Экспорт mesh-ресурса из такого определения блокируется до staging/write и
   не затрагивает существующий target.
3. `reuse` по умолчанию принимает только полное managed-определение и не
   меняет его. Incomplete, placeholder, unmanaged, malformed или partial
   identity claims блокируются.
4. `refresh` — явный opt-in. Root Collection сохраняется in-place, поэтому
   внешние instance users и scene links сохраняют указатель; меняется только
   содержимое.
5. Для всего рекурсивного замыкания заранее строится один action-plan по
   ResourceKey. Mixed create/reuse/refresh является штатным случаем.
6. Все создаваемые datablocks, external links, names, properties и refresh
   swaps журналируются в одной `MeshImportTransaction`. Injected failure
   после фактического swap восстанавливает старое содержимое, имена,
   properties и внешние users; частичного refresh нет.
7. Unmanaged dag4blend Collection не становится MH definition authority:
   `full-LOD/LOD0` требуют managed definition или canonical `.mesh.fbx`,
   а `structure-only` создаёт отдельное managed incomplete-определение.

### GAZ и diagnostics

Owner GAZ closure читается из `reference/dagor_fixtures/gaz53/`; обнаружены
`gaz53_b_random_cmp`, `gaz53_b_body_cmp`,
`gaz53_body_bc_random_cmp`. Ordered composite options:
`gaz53_bread_b_cmp`, `gaz53_wooden_b_cmp`, `gaz53_wooden_c_cmp` с
весами `1,1,1`. Все три documents дают exact `composite_json_bytes`
соответствующих DTO; display transforms и mirror edits bytes не меняют.

Единственный новый код среза:
`MH_E_DUPLICATE_RANDOM_OPTION_INDEX`. Registry counts:
**51 errors / 14 warnings**.
