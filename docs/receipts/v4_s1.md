## Выполнено

### Blender/Python

1. Удалены UID/passport/meshser, v1→v2 migration, legacy source index/resolver,
   manifest и mutation tooling вместе с зависимыми v2-тестами. Runtime и DTO
   больше не содержат UID-полей или dual-read старых форматов.
2. FBX exporter пишет обычный Combined-LOD FBX с `use_custom_props=False`.
   Render mesh из `.lodNN` получает временный `_lodNN`; совпадающий суффикс
   сохраняется, mismatched блокируется по временному правилу `OPEN-V4-3`, все
   временные имена восстанавливаются в `finally`.
3. Сохранены сбор geometry/aux/groups, `UCX_`/`_cls_*`/`SOCKET_`, null-node
   hierarchy, parent closure `MH_E_PARENT_OUTSIDE_RESOURCE`, dense LOD,
   material-slot subset, centimeter context, sibling staging и `os.replace`.
4. Centimeter context масштабирует временные копии Mesh, а не live datablock:
   исходные координаты/shape keys и datablock pointers остаются точно прежними.
5. Неканоничные имена строго отклоняются по `[a-z0-9_]+` без sanitize/lowercase.
   До решения `OPEN-V4-4` используется зарегистрированный
   `MH_E_NON_ASCII_RESOURCE_NAME`.
6. Material/Composite DTO сделаны name-keyed. Полные S2/S3 операции явно
   fail-closed; `Export Materials` блокируется до любой публикации FBX, поэтому
   transitional UI не оставляет частично изменённое source-дерево.

### UE plugin

1. Удалены passport reader/validation, UID resolver/codecs/assets/factory и
   зависимые v2 diagnostics/tests. `IMHSourceResolver` переведён на
   `FMHResourceKey {Kind, LogicalName}` с kind-sensitive equality/hash.
2. Scanner срезает полное `.mesh.fbx`, распознаёт material/composite и девять
   texture extensions из 08 §5, строго отклоняет case/noncanonical stem,
   допускает одинаковый stem разных kind и блокирует same-kind duplicates.
3. Нормативные `MH_E_AMBIGUOUS_RESOURCE_NAME` и
   `MH_W_DUPLICATE_RESOURCE_NAME` зарегистрированы в Python registry и golden
   list; итоговые счётчики — `36 E / 16 W`.
4. Stable snapshot подтверждает не только повторный список путей, но и повторный
   stable read/raw hash каждого валидного payload. Atomic replace по тому же
   пути больше не может оставить старый hash в успешно принятом snapshot.
5. Scan/resolve/analyze/plan и scope используют ResourceKey. Raw bytes хэшируются
   engine-native BLAKE3-160 (`blake3-160:<40 lowercase hex>`); добавлен точный
   empty-input vector.
6. Ledger оставлен компилируемым и явно `bIsDeprecated = true` до S4. Его
   transitional rows name-keyed; path обязан быть canonical root-relative POSIX
   без сегментов `.`/`..`, но легальные имена каталогов вроде `models..old`
   разрешены; raw hash/asset/timestamp/status валидируются fail-closed. Raw JSON
   `asset` проверяется через `FPackageName::IsValidObjectPath` до построения
   `FSoftObjectPath`, поэтому parser не может молча превратить плохую строку в
   пустой optional path.
7. Старые diagnostic tags не переиспользованы для несовместимых v4 bytes:
   `MHAnalyzeSources` сохраняет console Analyze/Plan, `-writeledger` и
   `-report` дают exit 2 без файла; v2 FBX dump commandlet/UI удалён до
   owner-решения `OPEN-V4-5` и mapper-facing этапа S5.

## Нормативные вопросы и временные правила

- `OPEN-V4-1` остаётся открытым: nested filesystem aliases блокируются.
- `OPEN-V4-3` добавлен для already-mismatched `_lodNN`; временно export
  блокируется `MH_E_INVALID_LOD_HIERARCHY`, без repair.
- `OPEN-V4-4` добавлен для общего кода noncanonical logical name; временно
  strict reject использует существующий `MH_E_NON_ASCII_RESOURCE_NAME`.
- `OPEN-V4-5` добавлен после review несовместимых diagnostic schemas. Временно
  новые v4 bytes не получают старые `:1` tags: structured report/dump отключены,
  console Analyze/Plan сохранён.

Новых нератифицированных machine codes не вводилось. Два добавленных duplicate
codes прямо заданы 08 §2.
