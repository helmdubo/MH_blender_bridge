## 5. Shared definition pool и инвалидация

`UMHCompositeDefinitionSubsystem` — `UEditorSubsystem`, хранящий только
успешные immutable `TSharedPtr<const FMHRandomSourceGraph>`. Exact entry key:

```text
(root ResourceKey,
 root AppliedHash,
 ClosureHash,
 ActorClassRegistry revision,
 MHStaticMeshImporterVersion)
```

Дополнительные `SourceHash`, live receipt и unique-claim проверки являются
fail-closed admission metadata, а не шестой частью cache key. `ClosureHash`
повторно вычисляется из сохранённого immutable graph перед hit. Изменение
`ActorClassRegistry` увеличивает session revision и отзывает все определения.

Targeted reimport использует существующий
`MHNotifyGeneratedResourceChanged`/`PlacementDependencies`: subsystem отзывает
затронутое definition один раз **до** обхода акторов; первый actor строит новое
definition, остальные получают тот же graph. Global rebuild аналогично делает
один global revoke до batch. Новых watcher/delegate и новых точек создания
компонентов нет.

`AMHCompositeActor` сохраняет shared lease на immutable graph для действующего
plan, но не владеет отдельной копией compiled closure. Full rebuild по-прежнему
входит только через `PostRegisterAllComponents`-цепочку. `OnConstruction`,
orphan-union, appearance fast-path и `bPlacementEditMode` guard не менялись.
Runtime/cook actor и bridge не менялись.

## 10. Вопросы owner/reviewer

1. **Контекст:** после shared graph pool синтетический probe тратит
   `2120.3908 ms` в `LoadEndpoints`, тогда как `BuildAppliedGraph` —
   `17.5812 ms`; `WaitStaticMeshCompilation=0`.
   **Вопрос:** назначать ли отдельный срез для per-operation endpoint lookup /
   idempotent endpoint assignment?
   **Временное fail-closed допущение:** S6.5 заканчивается на definition graph;
   endpoint cache, async wait и scheduler не добавляются.

2. **Контекст:** в репозитории есть единственная version-authority,
   применимая к загружаемым mesh endpoints — `MHStaticMeshImporterVersion`;
   отдельной версии composite definition compiler нет.
   **Вопрос:** именно `MHStaticMeshImporterVersion` подразумевается пятым
   элементом S6.5 key, или reviewer ожидает отдельную compiler revision в
   следующей редакции контракта?
   **Временное fail-closed допущение:** используется существующая
   `MHStaticMeshImporterVersion`; новая version-authority и шестое измерение
   ключа не изобретаются.

3. **Контекст:** текущий root asset не хранит предварительно вычисленный
   `ClosureHash`; вычислить актуальный hash до lookup означало бы снова собрать
   всё замыкание. Pool хранит entry под exact five-part key, ищет кандидата по
   root, затем сверяет все доступные key inputs, live receipt/unique claim и
   пересчитывает `ClosureHash` из уже immutable cached graph. Изменения
   dependency отзываются существующими targeted notifications.
   **Вопрос:** считается ли такой двухступенчатый lookup нормативным для S6.5,
   или в будущем должен появиться отдельный precomputed closure revision input?
   **Временное fail-closed допущение:** новый serialized hash/authority не
   вводится; любой наблюдаемый mismatch или notification отзывает entry, failed
   admission не кэшируется.
