## Реализованный кандидат

1. `UMHSourceImporter` запускает production startup scan только после
   готовности Asset Registry. Пока registry/settings не готовы, ticker
   повторяет попытку без ложного завершения startup.
2. Добавлен `DirectoryWatcher`: события переводятся на game thread,
   дедуплицируются и исполняются одним batch после debounce не менее одной
   секунды. Во время PIE batch остаётся в очереди и выполняется после EndPIE.
   Incremental path использует один `UpsertPaths`; полный scan происходит
   только при startup, явном Scan или `RescanRequired`.
3. Порядок mutation зафиксирован как
   `texture → material → static_mesh → composite`. Texture stage вынесен в
   собственный managed importer с `UMHTextureSourceData`, шестью tags и
   binary-правилом `AppliedHash == SourceHash`.
4. Self-publish token остаётся in-memory single-shot: watcher-echo после
   atomic replace даёт `NO_CHANGE`, повторный реальный edit не подавляется.
5. Добавлены UI-команды в существующие UE-меню:
   `Scan Project`, `Import Changed`, `Show Duplicates`,
   `Find Broken References`, `Find Orphaned Assets`, `Publish Material`,
   `Publish Composite`; отдельные команды размещения —
   `Build`, `Break`, `Edit`, `Commit`, `Cancel`, `Rebuild` и
   `Delete MH Resource`.
6. Добавлены headless commandlets `MHScanSources`, `MHImportSources`,
   `MHValidateNames`, `MHVerifyMaterials`, `MHVerifyComposites`.
   `MHVerifyMaterials` и `MHVerifyComposites` проверяют также persisted
   `bLocallyModified` managed-мешей; `MH_E_*` даёт ненулевой exit.
7. Детерминированный JSON-отчёт имеет tag `mh.analyze_sources:4`, сортированные
   entries/diagnostics и пишется только под `Saved/Mimir` через sibling tmp,
   exact read-back и atomic replace. Пустой/escaping output fail-closed.
8. `AMHCompositeActor` хранит только soft asset reference и transform.
   Компоненты, placeholders, dependency keys и warnings — transient/derived.
   Компилятор строит упорядоченное view без чтения source-файлов; notify по
   ResourceKey пересобирает только зависимые загруженные actors и не требует
   пересохранения level.
9. Неразрешённые root/node mesh, actor и composite представлены красным
   bbox/text placeholder с `MH_W_UNRESOLVED_PLACEMENT`. Появление same-name
   ресурса и Rebuild/notify восстанавливает полноценное размещение.
10. Level subsystem реализует Build/Break/Edit/Rebuild/Delete. Build сначала
    полностью проверяет representability выбранных actors, затем создаёт
    source+managed asset; неподдерживаемый объект даёт
    `MH_E_UNREPRESENTABLE_SCENE_OBJECT` до mutation. Операции editor-level
    обёрнуты ровно в одну undo-транзакцию; derived-компоненты запечатаны вне
    Edit, а Edit меняет только transforms.
11. `OPEN-V4-23`: drop `.composite` из `source_root` игнорирует Content Browser
    target и импортирует в identity-derived generated path. Внешний drop
    открывает Adopt-диалог с folder/name, предзаполняет stem, валидирует
    canonical target, запрещает same-kind duplicate без overwrite, копирует
    exact bytes через sibling tmp + read-back + rename и затем вызывает тот же
    штатный importer. Cancel не создаёт файлов.
12. Зарегистрирован `MH_E_UNREPRESENTABLE_SCENE_OBJECT`; golden registry =
    `47 E / 14 W`.
13. Managed-текстуры с canonical logical suffix `tex_n` после import/reimport
    получают `SRGB=false` и `CompressionSettings=TC_BC7`. Эти настройки входят
    в exact-state check: `Import Changed` выполняет policy-check даже для
    equal-hash `NO_CHANGE`, поэтому устаревшие настройки исправляются in-place,
    а уже точное состояние остаётся без mutation.
14. Startup lifecycle не выполняет mutation из Asset Registry/EndPIE delegate:
    readiness только ставит quiet-clock, импорт идёт из штатного ticker после
    `>=1s`, вне PIE и вне другого импорта. Выход из PIE заново запускает quiet
    period и для startup, и для watcher batch. `Prompt` публикует немодальный
    Message Log notification; поздние Asset Registry/watcher callbacks после
    deinitialize отбрасываются.

## Полевой follow-up: startup, watcher, selection и shutdown lifecycle

Дата: 2026-08-25. Production-кандидат: `e511a07`.

По следующему owner field-test исправлены четыре связанные lifecycle-проблемы:

- после завершения startup source-pass один раз пересобираются все живые
  загруженные `AMHCompositeActor`; это устраняет неполные деревья, которые могли
  быть созданы `PostLoad` до готовности generated dependencies;
- watcher по-прежнему выполняет полную безопасную проекцию, но чистый
  self-publish/`NO_CHANGE` echo больше не печатает в Message Log весь план
  проекта. Изменившийся или заблокированный наблюдаемый ресурс, full rebuild и
  сессионные события остаются видимыми;
- `Build Composite` снимает selection до уничтожения исходных actor, а
  `AMHCompositeActor::Destroyed` немедленно снимает transient derived components.
  Глобальные notify/rebuild пропускают destroyed actor и миры в cleanup, поэтому
  старые hit proxies больше не ведут к actor с invalid flags;
- `ShutdownModule` обращается к `UToolMenus` только если подсистема ещё жива.
  Это закрывает owner crash на выходе в
  `FMimirCompositeEditorModule::ShutdownModule`.

Добавлены Automation-регрессии на однократный startup refresh, отсутствие
package-dirty при healing, фильтрацию watcher `NO_CHANGE` и невозможность
повторной регистрации placement-компонентов уничтоженного композита.

возвращает акторы уровня, но не удаляет файл.
