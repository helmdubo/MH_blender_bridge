## Выполненная ориентация

1. Три независимых read-only аудита разложили:
   - текущие scanner/resolver/analyzer/Ledger/composition seams и полный
     Ledger removal surface;
   - stock UE 5.7 `SQLiteCore`, Asset Registry API и будущие build boundaries;
   - S4 schema/state machine, dependency/GeneratedAssets/event semantics и
     acceptance-гейты.
2. Подтверждено, что `IMHSourceResolver`, `IMHChangeDetector` и
   `MHSourceComposition` позволяют локализовать SQLite backend без зависимости
   importer/compiler от SQLite. Существующий scanner уже даёт reusable
   classifier, allowlist, stable double-read/hash, alias/root protection,
   quarantine и deterministic duplicate ordering.
3. Точка startup после `AssetRegistry.OnFilesLoaded` существует в
   `UMHSourceImporter`. Material/Composite публикуются через общие low-level
   atomic writers, однако Adopt и Automation также вызывают их напрямую:
   publish recorder нельзя без решения навесить только на UI/subsystem wrapper.
4. Stock UE 5.7 предоставляет editor-совместимый `SQLiteCore` с
   `FSQLiteDatabase`/prepared statements/transactions/user-version/integrity.
   Будущая реализация потребует private module dependency и явный plugin
   dependency, поскольку `SQLiteCore` не enabled-by-default. Runtime/Engine
   менять не требуется.
5. Сформирован acceptance-план `Mimir.V4.ProjectIndex`: logical
   schema/rebuild parity, 10k resolve с counting scanner, move identity,
   rename/orphan, duplicate transitive blocking, exact-five GeneratedAssets,
   injectable self-publish classification и static Ledger purge.
