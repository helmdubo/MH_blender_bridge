# 15 — Срезы V5-S6.1.1 (hardening) и V5-S6.1.2 (collision/phmat)

Статус: **owner-решения ратифицированы 2026-08-30 в рабочей сессии**;
исполняется S6.1.1, S6.1.2 специфицирован и идёт следом. Основание:
настоящий GAZ-53 E2E (импорт 303 коллекций / 5155 объектов прошёл, экспорт
заблокирован контрактным дефектом LOD-материалов) и внешний аудит R3.
Контекст и предыдущие поправки — `docs/13_v5_s6_1_dag4blend_bridge.md`,
программа — `docs/14_v5_ue_editor_program.md`.

## 1. Owner-решения 2026-08-30

1. **LOD material union (закрывает `MH_E_LOD_SLOT_NOT_IN_BASE`).**
   Правило «слоты LOD ⊆ слоты LOD0» было синтетическим допущением; реальный
   контент (39/39 меш-коллекций GAZ) его опровергает: художник свободно
   выбирает материалы каждого LOD (в т.ч. упрощённые `rendinst_simple*` на
   дальних). Новый контракт: материальный список меша — детерминированно
   упорядоченное объединение слотов всех LOD; каждый LOD мапит свои секции
   в этот список; UE-импортёр назначает per-LOD section materials (нативная
   механика StaticMesh). Механика импорта материалов и LOD должна быть
   согласована writer ↔ parser ↔ UE.
2. **Перезаписывать FBX всегда.** LOD-set guard НЕ вводится: повторный
   экспорт пишет текущие данные сцены; если при этом теряются LOD — это
   ответственность художника, контроль за LOD у художника. (Подтверждает и
   расширяет закрытие OPEN-V5-22.)
3. **`cls` — технический материал Blender** (сплошной зелёный, shader
   `gi_black`, в Dagor не рендерится). В экспорт UE5 не попадает вообще:
   ни слотом FBX, ни `.material` в замыкании. Коллизия в UE5 не рендерится.
4. **Path (a)** (`core/dagor_composites.py`, строгий BLK reader) —
   пометить **legacy/limited** и убрать из рекомендуемого UX. Паритет не
   реализуется; production-маршрут — только dag4blend scene adapter.
5. **Completeness admission — структурные проверки**, не история флагов
   импорта: пустая nested-коллекция с даговской identity при существующем
   непустом source `.composite` → reuse source либо блок, никогда не
   перезапись пустотой.
6. **Текстуры**: Copy/Remap остаётся ручным шагом художника (две кнопки).
   P2-замечание: наша функция смены путей медленнее dag4blend (тот, видимо,
   использует индексацию/кэш проекта) — ускорить через существующий
   source-индекс при следующем perf-проходе.
7. **Проекция внешних имён Dagor-материалов** не ослабляет Source Protocol:
   канонический output по-прежнему принимает только `[a-z0-9_]+`. На входной
   границе материалов регистр ASCII понижается, а последовательности внешних
   ASCII-разделителей и пунктуации проецируются в `_`:
   `Material #2644` → `material_2644`,
   `13 - Default` → `13_default`. Unicode, управляющие символы и имена без
   токенного содержимого остаются fail-closed. И `.material`, и имя material
   slot внутри FBX используют один токен; временное транспортное переименование
   всегда откатывается, сцена не мутирует. Эквивалентные claimants объединяются;
   отличающиеся получают стабильный суффикс по правилу §2.3. Коллизия уже
   disambiguated-токенов остаётся fail-closed `MH_E_AMBIGUOUS_RESOURCE_NAME`.
   Контракт texture/resource stems не расширяется: пунктуация в них
   по-прежнему отказ.

## 2. Scope V5-S6.1.1 — hardening

1. **LOD material union** (решение 1): writer `scene/export_fbx.py`
   (снять `MH_E_LOD_SLOT_NOT_IN_BASE`, объединение слотов, per-LOD
   маппинг секций), reader `core/mesh_nodes.py` (та же грамматика),
   UE `MHStaticMeshImporter` (per-LOD section materials). Замыкание
   `.material` собирается со слотов всех LOD (уже так).
2. **Исключение `cls`/коллизий из render-пути** (решение 3): узлы
   коллизии (`*_cls_phys*`, `*_cls_trace*`) и материал `cls`
   (shader `gi_black`) распознаются и не попадают в render payload и в
   material closure; предупреждение с перечнем пропущенного. Транспорт
   коллизий — S6.1.2, здесь только чистое исключение.
3. **Дубликаты `.00N`**: суффиксы Blender-частей одного static mesh
   нормализуются (имя ресурса — имя `.lods`-коллекции без суффикса;
   `sovmod_electric_a_switch_a.lods` → static mesh
   `sovmod_electric_a_switch_a`). Для материалов эквивалентные по каноническому
   содержимому `X`/`X.00N` сливаются в один токен `X`. **Полевая поправка
   owner 2026-08-31** по реальной четвёрке `glass`, `Glass`, `glass.001`,
   `glass.002`: расходящееся содержимое не затирается и не блокируется — каждый
   отличный fingerprint получает отдельный стабильный токен
   `X_<sha256(authoring datablock name)[:12]>`. Тот же токен используется в
   FBX и `.material`; исходные имена и параметры сцены не мутируют.
4. **Completeness admission** (решение 5) по режимам: root_only — без
   требований к геометрии сцены; composite_closure и include_all —
   nested из сцены принимается только непустой; пустая nested definition
   при непустом source → **reuse source** (пустота никогда не публикуется
   поверх), при отсутствии source → блок с точным именем коллекции.
   Пустой root — отказ во всех режимах экспорта.
5. **Mixed-root block**: generic MH-ридер перестаёт интерпретировать
   даговскую identity (`gameobj → actor`, `prefab → mesh` в
   `_collection_instance_identity` удаляются); любая legacy
   dag4blend-коллекция внутри native MH-формы — отказ «mixed scene
   representation». Отрицательный тест обязателен.
6. **Save/reopen гейт**: real import → save → reopen → export даёт
   байт-идентичный canonical `.composite` (фиксация контракта порядка
   `Collection.objects`).
7. **Path (a) legacy-баннер** (решение 4) в коде/README; из
   рекомендуемого UX убран.
8. **Документация**: консолидация 13 в единую действующую редакцию,
   актуализация README/receipt (замечание аудита о «тексте с поправками
   сверху» принято).

Acceptance среза: GAZ-53 E2E из сохранённой сцены
(scratch `gaz53_b_random_cmp_imported.blend`) проходит include_all в
чистый Source Root (текстурные пути перебиты скриптом на фактические
CDK-файлы — эмуляция ручного Remap); повторный экспорт перезаписывает
FBX; сцена не мутирует; существующие suite зелёные.

## 3. Scope V5-S6.1.2 — collision + phmat

Основание — owner-спека 2026-08-30 (дословные примеры сохранены).

1. **Оверлей-патч №2 dag4blend** (по образцу патча зеркал weight/type):
   данные физматериала, хранящиеся dag4blend во внешнем тексте,
   записываются в custom properties меша коллизии:

   ```text
   collision:t="mesh"        # вид коллизии: mesh | box | convex | capsule
   phmat:t="wood"            # физматериал
   isPhysCollidable:b=yes    # физика: ходьба, техника, плейсинг
   isTraceable:b=no          # трейсы: стрельба, декали, подбор
   ```

   Полный словарь script{}-блока Dagor: `renderable:b` (визуальная
   геометрия ноды — неактуально), `collidable:b=yes` на render-меше
   превращает его в коллизию — вынесено за скобки, будущие версии.

2. **FBX-транспорт и UE-парсинг**: узлы `*_cls_phys*` → **Simple
   Collision** UE, узлы `*_cls_trace*` → **Complex Collision**; каждый
   узел получает свой `UPhysicalMaterial` по имени phmat (набор ассетов
   физматериалов предварительно создаёт owner). `.00N`-части сливаются в
   коллизию одного static mesh.

3. **Реестр phmat** — `docs/reference_notes/dagor_phmat_registry.md`
   (перенесён owner-таблицей Enlisted). Имя phmat — английский токен.

4. **Конкретные носители (зафиксировано Lead 2026-08-30 по owner-спеке).**

   - Blender ID custom properties коллизионного mesh-объекта (пишет
     оверлей-патч №2, по прецеденту зеркал `weight:r`/`type:t`):
     `collision:t`, `phmat:t`, `isPhysCollidable:b`, `isTraceable:b` —
     дословные даговские ключи.
   - FBX-carrier: пользовательские свойства Model-узла
     `mh_collision` = `"phys"` | `"trace"`,
     `mh_collision_shape` = `"mesh"` | `"box"` | `"convex"` | `"capsule"`,
     `mh_phmat` = токен реестра. Пишутся Blender-экспортером
     (`use_custom_props`), читаются `parse_mesh_fbx` и UE-импортёром.
   - Классификация узла коллизии остаётся material/name-first из S6.1.1;
     свойства обогащают её. Узел без `phmat` транспортируется без
     физматериала с предупреждением (сцены, импортированные до патча).
   - **Роль (phys/trace), ратификация Lead 2026-08-30 по реальному
     контенту** (в GAZ только 2 из 54 коллизий несут name-токен;
     остальные объявляют роль ратифицированными декларациями §3.1):
     name-токен `phys`/`trace` авторитетен, где присутствует; при
     молчащем имени роль определяет пара `isPhysCollidable:b` /
     `isTraceable:b` (ровно один true); противоречие имени и деклараций —
     имя побеждает, расхождение репортится; ни имени, ни валидной
     декларации (обе true/обе false/отсутствуют) → распознанный drop
     с предупреждением, семантика не изобретается.
   - Известный разрыв round-trip: узел коллизии, распознаваемый только
     покраской, не переживает MH import→export (импорт `.mesh.fbx` не
     восстанавливает `mh_*`-свойства в Blender). Реальный контент несёт
     `cls`-токен в имени и переживает; закрытие разрыва — включение
     чтения custom properties при импорте, отдельный кандидат.
   - UE: `*phys*` → Simple Collision (mesh→convex-элемент по вершинам
     узла, box/convex/capsule → соответствующие элементы);
     `*trace*` → Complex Collision через отдельный trace-меш
     (секции по phmat; физматериал секции несёт материал секции).
     Если UE 5.7 не поддерживает per-shape физматериал simple-элементов
     нативно — реализуется per-mesh (доминирующий phmat) с честным
     отчётом ограничения owner'у, семантика не изобретается.
   - Поиск ассетов `UPhysicalMaterial`: по имени, равному токену
     реестра, в настраиваемом пути плагина (default
     `/Game/PhysicalMaterials`); отсутствующий ассет — предупреждение
     без отказа. Owner создаёт набор из 23 токенов реестра.
   - Заодно закрывается UCX-хвост union из S6.1.1: обе стороны
     переходят на render-only union; UCX-узлы — только коллизия.

- Паритет path (a) — отклонён (решение 4).
