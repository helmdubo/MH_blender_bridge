# Composite Edit — панель наполнения и навигации

Status: IMPLEMENTED. Automated verification passed; owner field acceptance pending.
Evidence: `docs/receipts/composite_authoring_panel.md`.
Owner request 2026-09-09 после проверки модели Dagor
в `docs/reference_notes/dagor_assetviewer_composit_panel_20260908.md`, §11.
Этот срез расширяет существующий Edit Mode и его inline Composite Outliner.

## Пользовательская модель

- Авторский node имеет transform/параметры, собственное содержимое и дочерние
  nodes. Содержимое: пусто, ссылка на ассет или взвешенные варианты (`entity`).
- Entity — вариант содержимого node, без собственного transform и детей.
  Random показывается как следствие наличия вариантов; один вариант тоже Random.
- В MH у всех node есть authored TRS с identity по умолчанию. Отсутствие поля
  transform в canonical JSON не означает запрета трансформации. Существующие
  profile/inline placement узлы не допускаются к обычному transform editing;
  sampled transform не записывается обратно как authored.
- Вид панели отделяет содержимое от transform и дочернего дерева. Inspector
  объясняет, когда узел — locked context или его transform procedural.

## Дерево и переходы

- Полное дерево закреплено за placement активной сессии; редактируемая ветка
  различима, остальной контекст приглушён и не становится доступным для записи.
- При открытии вложенного Edit автоматически раскрываются все предки текущего
  occurrence, а строка редактируемого композита видна без ручного поиска.
- При scene selection раскрывается путь к соответствующему authored node и
  строка прокручивается в видимую область. Обычный refresh не раскрывает всё
  дерево заново и не сбрасывает пользовательское раскрытие соседних веток.
- Через панель доступны переходы в другой подкомпозит и к родителю/root по
  RequestSwitch. Owner уточнил: объект сессии, Mode и Toolkit сохраняются,
  меняется определение внутри сессии; выход и повторный вход запрещены.
  Scope epoch меняется, чтобы старые callbacks не действовали на другой draft.
  Камера и Game View остаются под контролем автора.
- Owner подтвердил сообщение Save / Discard при dirty switch. Закрытие сообщения
  без решения (Stay) и ошибка Save сохраняют текущую сессию и draft.
  Одновременное редактирование нескольких определений не подразумевается.
- Save при переходе публикует текущее определение, но не закрывает сессию.
  Финальные Save/Cancel в панели режима по-прежнему завершают её. После
  успешного перехода Undo предыдущего определения очищается; ошибка до записи
  сохраняет предыдущий draft и его историю. Если запись уже завершилась, а
  целевой occurrence исчез, текущий scope остаётся открытым и чистым; Undo
  очищен на границе публикации. Обновляются breadcrumb и scope
  дерева без пересоздания панели. Невалидный target проверяется до записи/Discard.

## Наполнение из Content Browser

- Add nodes читает актуальное множественное выделение Content Browser и создаёт
  по одному node со ссылкой и identity local transform на каждый ассет.
- Выбранный authored node задаёт parent. Корень редактируемого определения
  задаёт список корневых nodes draft. Внешнее определение не изменяется молча:
  для добавления внутрь его определения требуется перейти Edit Contents.
- Допуск детей под негрупповые nodes открывается только с проверкой текущей
  цепочки parser → compiler → projection → writer; wire-формат не расширяется.
- Add entities добавляет варианты веса 1 выбранному authored node. Для прежней
  одиночной ссылки она сохраняется первым вариантом веса 1; пустая группа не
  получает скрытого Empty-варианта. NodeId, authored TRS, metadata и дети
  сохраняются. Существующие Random дополняются, а не заменяются.
- Веса изменяются вручную; рядом отображается вычисленная вероятность.
  Отрицательные/нечисловые веса и нулевая общая сумма отклоняются. Удаление
  последнего варианта очищает содержимое (Group), сохраняя node и детей.
- Owner допускает ограничение этого среза уже управляемыми MH meshes и
  composites с существующим логическим именем. Обычные UE ассеты без MH identity
  не получают выдуманный source resource и явно отклоняются.
- Пакетное добавление атомарно: все выбранные ассеты и transform проверяются
  до mutation. Ошибка одного не оставляет частично добавленные nodes/options.
  Успешный пакет — одна Undo-транзакция, один refresh, выбор созданных nodes.
  Drop выше/ниже строки сохраняет порядок выбранных ассетов среди соседей;
  drop на Random добавляет варианты, на остальные nodes — детей.
- Отложенные команды привязаны к текущей session/epoch и authoring revision;
  старые callbacks не меняют новый draft или другой option после перестановки.
- Перед preview проверяется цикл по логическим именам в объединённом графе
  published + draft, включая невыбранные варианты. Цикл не запускает обход:
  draft остаётся доступен для исправления/Undo с диагностикой preview, а
  неудачный переход восстанавливает предыдущий scope. Save повторяет допуск
  графа до применения ассета и записи source; цикл не пересекает эту границу.

## Сохраняемые границы и будущее расширение

Сохраняются native secondary selection, быстрый drag, preview SMC и ISM вне
Edit, единый Cancel/Esc без вопроса и явный Save без overwrite prompt.
Добавление не публикует source, не запускает source scan/proof или импорт.

Будущие срезы: расстановка/симуляция выбранных ассетов относительно node;
выделение node и его authored subtree в отдельный composite asset и экспорт
этого ассета в исходный файл. Сейчас эти операции не исполняются. Пакетная
команда принимает явные transforms, чтобы последующая расстановка могла
использовать тот же атомарный authoring путь.

## Приёмка

1. Вложенный Edit с несколькими одинаковыми occurrences раскрывает именно
   выбранный occurrence; scope и selected node видны; locked context не editable.
2. Переход parent/root/sibling работает через существующий switch, с сохранением
   dirty policy и без camera jump. Обновления и выборы не раскрывают всё дерево.
3. Multi-add nodes и variants; invalid mixed batch; conversion с детьми;
   финальное удаление варианта; веса; Undo/Redo; stale command rejection.
4. Children негруппового parent сохраняются через writer/parser и preview;
   Empty Random не выключает детей. Процедурные узлы остаются защищены от drag.
5. Сборка plugin без Engine changes, focused Automation, существующая регрессия
   Edit/recipe, RHI-проверки. Полевую удобность оценивает owner.
